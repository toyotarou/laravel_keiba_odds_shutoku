追加対応まとめ

2026年8月29日

ご要望いただいた内容をもとに、馬眼力の分析精度向上と画面表示の強化を行いました。今回の対応は大きく4つのテーマです。

1. AIへの指示書（プロンプト）の全面精緻化

目的・背景

馬眼力のAIは、膨大なオッズデータを読んで「どの馬を選ぶか」を判断しています。その判断の土台になるのが「指示書（プロンプト）」と呼ばれる文章です。この文章が曖昧であれば、AIの判断も曖昧になります。

今回、以下の5つの観点でこの指示書を書き直しました。すべて「AIが今まで感覚的に判断していた部分を、明確なルールとして定義する」ことを目的としています。一言で言えば、「AIが迷わないよう、判断基準を細かく言語化した」対応です。

依頼主向け ① 断層の強さを3段階で定義

変更前
断層があるかないか、2択でしか判断できていなかった。「少し開いている断層」も「大きく開いている断層」も同じ「★断層」として扱われており、強さの違いをAIが区別できていなかった。
変更後
断層の大きさに応じて「弱・強・非常に強い」の3段階でAIが認識するようになった。強い断層ほど、AIが重要なシグナルとして扱う。

「断層があること」と「断層がどれほど大きいか」は全く別の情報です。この変更により、AIが断層の重さを正確に評価できるようになりました。

依頼主向け ② レースタイプごとの波乱度目安を設定

断層構造タイプ（A〜E）ごとに「このタイプのレースは波乱度がこのくらいになりやすい」という目安をAIに渡しました。

  • タイプA（上位に強い断層が集中）→ 波乱度 1〜2（堅い決着が多い）
  • タイプB（断層が1か所）→ 波乱度 2〜3（やや荒れる可能性）
  • タイプC（断層が下位圏）→ 波乱度 3（中程度の荒れ）
  • タイプD（断層なし・混戦）→ 波乱度 4〜5（大きく荒れやすい）
  • タイプE（単複で断層位置が異なる）→ 波乱度 4〜5（読みにくい）

これをベースに、次の「修正ルール」でレースの実際の資金動向も加味した最終的な波乱度を決定します。

依頼主向け ③ 波乱度の修正ルールを追加

タイプだけで決まる目安に加えて、「こういう場合は波乱度を上げる・下げる」という具体的な修正条件を5つずつAIに渡しました。タイプという「構造的な特徴」だけでなく、実際の資金の動きも加味して波乱度を補正する仕組みです。

波乱度を上げる条件の例：複数の人気薄馬に継続的な複勝資金流入がある、複勝断層と単勝断層の位置が一致しない、など

波乱度を下げる条件の例：1〜3番人気の複勝オッズが全体的に下落継続している、断層が6番人気以内に2か所以上ある、など

具体的なケース
「タイプD（混戦）なのに1番人気への資金が明らかに集中している」という場合、構造だけ見れば波乱度は高いはずですが、修正ルールにより波乱度が下方修正されます。「見た目は混戦だが、実際の賭け方は堅い」という判断をAIがより正確にできるようになりました。

依頼主向け ④ 選出馬の最低スコアを明示

変更前
「何頭選んでください」という指示だったため、根拠が薄い馬でも頭数を埋めるように選んでしまうことがあった。「5頭選べ」と言われると、5頭のうち1〜2頭は弱い根拠で選ばれていた。
変更後
スコアの最低ラインを設定し、「基準に達しない馬は無理に選ばなくてよい」と明示した。頭数を埋めることより、根拠のある馬だけを選ぶことを優先させた。
  • 本候補：70点以上
  • 補欠：60〜69点
  • 人気薄注目馬：55点以上 かつ 複勝への資金流入が確認できること

「頭数を埋めることより、根拠の質を守ること」を優先させた変更です。上限頭数はあくまで天井であり、基準に届かなければその枠を使わなくてよい、という方針になりました。

依頼主向け ⑤ 穴馬の選出条件を人気帯別に分離

変更前
「7番人気以下」をひとまとめにして同じ条件で判断していた。中穴（7〜10番人気）と大穴（11番人気以下）の判断基準が同じだったため、大穴馬が緩い条件で選ばれるリスクがあった。
変更後
7〜10番人気と11番人気以下を別の基準で評価するようにした。

7〜10番人気：8つの条件のうち3つ以上を満たせば選出対象
11番人気以下：5つの厳格な条件をすべて満たす場合のみ選出（根拠が揃った馬だけ）

大穴馬ほど選出のハードルを上げることで、「なんとなく面白そう」という選出を防ぎ、根拠のある大穴だけが候補に残るようになりました。

エンジニア向け 変更箇所

対象：AiController.php — _getAiAnalysisPrompt() 内のみ。PHP処理・出力フォーマットへの変更なし。

  • 断層強度注記を 比率2.00以上=★断層、2.50以上=★★強い断層、3.00以上=★★★非常に強い断層 に変更
  • タイプ別ルールに波乱度目安を追記（A=1〜2, B=2〜3, C=3, D=4〜5, E=4〜5）
  • 波乱度修正ルールセクションを新規追加（上げる5条件・下げる5条件）
  • 推奨頭数上限ルールに最低スコア閾値を追記（本候補70点、補欠60〜69点、人気薄注目馬55点+複勝流入）
  • 混戦時の下位選出条件を7〜10番人気（8条件中3つ以上）と11番人気以下（5条件すべて必須）に分離
  • 下位進入度・大穴進入度の評価優先度を指示するセクションを新規追加

2. レース構造に応じた推奨頭数の自動調整

目的・背景

これまでAIは「出走頭数が8頭以下なら4頭、13頭以下なら5頭、それ以上なら6頭」という機械的な判断をしていました。しかしこれは、レースの「荒れ度合いの構造」を全く無視したルールです。

同じ16頭立てでも「上位に強い断層があって固いレース」と「断層なしの混戦」では、適切な選出頭数も選ぶべき人気帯も全く異なります。今回、レースの断層構造タイプ（A〜E）に応じて、推奨頭数と人気帯の上限を自動的に変える仕組みを導入しました。

依頼主向け タイプ別の人気帯・頭数設定

単に「何頭選ぶか」ではなく、「どの人気帯から何頭まで選ぶか」をタイプごとに定義しました。固いレースで無理に穴馬を探す必要はなく、荒れるレースでは穴馬の枠を多く確保する、という設計です。

タイプ特徴1〜6番
人気		7〜10番
人気		11番〜
人気		合計
上限
A上位支配・固い最大4頭なしなし4頭
B断層1か所最大4頭最大2頭最大1頭7頭
C断層が下位圏最大3頭最大3頭最大1頭7頭
D断層なし・混戦最大3頭最大3頭最大2頭8頭
E単複乖離・読みにくい最大3頭最大3頭最大1頭7頭
読み方の例
タイプAのレースでAIが選ぶのは「1〜6番人気の中から最大4頭」だけです。7番人気以下は原則として選出対象外になります。逆にタイプDの混戦レースでは、穴馬（11番人気以下）まで含めて最大8頭を選ぶことができます。ただしこれはあくまで「上限」であり、スコアが基準に届かない馬は選ばなくてよいというルール（①〜④の内容）は守られます。

この変更により、「固いレースで大穴馬が無理やり選ばれる」「混戦レースなのに上位人気しか選ばない」という不自然な選出がなくなります。

3. 断層強度フラグの3段階化

目的・背景

AIに渡す断層テーブルには、人気が隣り合う馬どうしのオッズ比率が表示されています。たとえば「2番人気のオッズ÷3番人気のオッズ」が2.5なら、その間に断層がある、という計算です。

これまで比率2.00以上の箇所はすべて「★断層」と同じマークで表示していましたが、比率2.1の断層と比率4.0の断層では市場のシグナル強度が全く異なります。今回、断層の大きさをAIが一目で読み取れるよう、3段階のフラグに変更しました。

依頼主向け 変更内容

変更前
比率2.00以上はすべて「★断層」と表示。強さの違いが区別できず、AIが全て同じ重さのシグナルとして扱っていた。
変更後
★断層　　　　→ 比率2.00以上（通常の壁）
★★強い断層　→ 比率2.50以上（明確な壁）
★★★非常に強い断層 → 比率3.00以上（際立った壁）

AIは★の数が多いほど「ここに大きな壁がある」と強く認識する。
実際の効果
たとえば2番人気と3番人気のオッズ間に「★★★非常に強い断層」がある場合、AIは「2番人気以内でほぼ決まる可能性が高い」と判断する材料として強く重視します。同じ断層でも強さによって意味が変わることを、AIが正確に扱えるようになりました。

逆に「★断層が複数点在しているだけ」というレースと「★★★が1か所だけ」というレースでは、後者のほうが明確な境界線があると読むべきで、この違いが選出の質に反映されます。

エンジニア向け 変更箇所

対象：AiController.php — 単勝断層テーブル（L908-911）・複勝断層テーブル（L937-940）

三項演算子の2値判定を if / elseif の3段階に置き換え。単勝・複勝とも同一ロジック。

// Before $gapFlag = $gapRatio >= 2.0 ? ' ★断層' : ''; // After if ($gapRatio >= 3.0) { $gapFlag = ' ★★★非常に強い断層'; } elseif ($gapRatio >= 2.5) { $gapFlag = ' ★★強い断層'; } elseif ($gapRatio >= 2.0) { $gapFlag = ' ★断層'; } else { $gapFlag = ''; }

4. 波乱度・下位進入度・大穴進入度をアプリに表示

目的・背景

「このレースは波乱度が高い」という情報だけでは、実際に穴馬を買うかどうかの判断には使えません。「荒れる」といっても、「1〜6番人気の中で着順がバラける」のか「7番人気以下が実際に飛び込んでくる」のかは全く別の話だからです。

今回、AIが毎回レース全体の性質を3つの指標で個別に評価・出力し、それをアプリ画面に表示する機能を追加しました。「荒れる方向性」をより具体的に見せるための対応です。

依頼主向け 3つの指標の意味

  • 波乱度（1〜5）：そのレース全体の「荒れやすさ」。1が最も堅く、5が最も波乱含み。オッズの動き・断層構造・流入パターンを総合して判断。
  • 下位進入度（1〜5）：7〜10番人気の馬が5着以内に入り込む可能性。複勝への継続的な資金流入が確認できる中穴馬がいるかどうかが主な判断材料。
  • 大穴進入度（1〜5）：11番人気以下の馬が5着以内に入り込む可能性。タイプD/E限定で、複勝流入ランクが高い馬がいるときのみ数値が上がる。

依頼主向け 3指標の組み合わせで何がわかるか

3つの数字を組み合わせることで、「どう荒れそうか」の具体的な方向性が見えてきます。

パターン例①「荒れるが穴馬は来ない」
波乱度4・下位進入度2・大穴進入度1
→ 荒れてはいるが、7番人気以下が来る根拠は薄い。上位人気の中での波乱。この場合は無理に穴馬を選ばず、1〜6番人気の中で意外な馬を狙うのが正解。
パターン例②「中穴が来そう」
波乱度4・下位進入度4・大穴進入度1
→ 全体的に荒れており、かつ7〜10番人気への資金流入が見られる。11番人気以下まで手を広げる根拠はないが、中穴を積極的に拾いに行ってよいレース。
パターン例③「大波乱の可能性あり」
波乱度5・下位進入度4・大穴進入度3
→ 全ての指標が高い、本物の荒れレース。11番人気以下の馬への資金流入も確認できており、大穴も含めた幅広い選出が正当化される局面。

これら3指標は、馬の選出リストの上に★マークで表示されます。数字だけでなく星の数で視覚的に把握できる設計です。

エンジニア向け 変更箇所（全4ファイル）

既存の出力パーサー（parseUpsetRaceValue()・parseAnalysisText()）への影響はゼロ。新しい行は別のプレフィックス（レース指標|）で識別するため完全に独立。バックエンドのみ先行デプロイ済み。Flutterを旧バージョンのまま動かしても新しい行は無視されるため、エラーにはならない。

  • functions.dart（Flutter）：parseRaceMetrics(String text) を新規追加。レース指標| で始まる行をパースして Map<String,int> を返却。
  • ai_analysis_display_alert.dart（Flutter）：_raceMetrics 状態変数追加・フェッチ時パース・_buildRaceMetrics() / _buildMetricItem() ウィジェット追加。
  • total_forecast_display_alert.dart（Flutter）：同上。

今回の対応 全体まとめ

今回の4つの変更は、それぞれ独立した改善ではなく、ひとつの方向性でつながっています。

断層の強さを3段階化（3.）することで、AIが渡されるデータの解像度が上がります。その解像度の高いデータをもとに、プロンプトの精緻化（1.）によってAIが正確な波乱度・進入度を判断し、タイプ別の推奨頭数（2.）によって適切な人気帯から適切な頭数を選出します。そしてその判断結果がアプリ上の3指標表示（4.）として可視化される、という流れです。

一言で言えば、「データの精度 → AIの判断精度 → 選出の精度 → ユーザーへの見せ方」という一連の流れを、全ての段階で底上げした対応です。
