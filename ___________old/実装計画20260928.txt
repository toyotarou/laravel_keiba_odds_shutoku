■ 1. N と C の算出
────────────────────────────────

  N = 取消・除外反映後の実出走頭数
      既存の $horseCount2nd（t_horse_odds_finder_horses のCOUNT）が該当。
      ※取消・除外が反映されているか要確認。されていなければ条件追加。

  C = N≦8   → min(N,4)
      9〜13  → 5
      14〜15 → 6
      N≧16  → 7

  ・N<1 なら予測中止
  ・出走馬一覧と馬データの頭数が不一致 → Cを下げず「データ不整合エラー」
  ・AIに計算させない。PHPが算出して埋め込む


■ 2. プロンプトへの動的埋め込み（3つ）
────────────────────────────────

  {{ACTIVE_RUNNER_COUNT}}              … N
  {{TARGET_SELECTION_COUNT}}           … C
  {{PROTECTED_LONGSHOT_HORSE_NUMBERS}} … 保護対象の馬番一覧（空可）

  触る場所: _getAiAnalysisPrompt() の $lines[]
  ・「最大C頭まで」→「C頭を出力」に指示を変更
  ・2nd AI は従来どおり0〜5頭（1st AI専用のC頭指示は除去・置換する）

  ★ここを変えるとプロンプト本文が変わる。
    過去レースの再実行は --remerge では効かず、Claudeから呼び直しになる。

■ 4. 人気薄保護枠（新規・いちばん大きい）
────────────────────────────────

  対象: 6分前の単勝人気が7番人気以下、かつ C≧4 のときだけ

  3群のうち【異なる2群以上】でそれぞれ1つ以上 true なら保護対象
  （同じ群で複数trueでも1群と数える。欠損は「不明」で数えない）

   時系列流入群
     L1 複勝最小オッズが連続3区間以上低下、かつ9分前→6分前も低下
        → $h['fuku_min_series'] の全時点から判定
     L4 9分前→6分前に単勝と複勝最小がともに2％超低下
        → $h['last3min_tan_rate'] / $h['last3min_fuku_rate']

   相対支持群
     L2 6分前の複勝人気順位が単勝人気順位より2順位以上上位
        → $b6FukuPopMap / $b6TanPopMap
     L3 同一人気帯内の複勝流入ランクが1位または2位
        → $h['fuku_inflow_rank']

   過小評価・実績群
     L5 予測補正OPIが0.95以下
        → $h['estimated_opi']
     L6 類似レース統計 サンプル30件以上 かつ 5着以内率70.0％以上
        → $similarStatsMap

  ※回収率系（過去/OPI帯別/フェーズ別/40%閾値/F8）はL1〜L6に含めない

  AI側:
    1st AI … リスト該当馬のうちおすすめ度最高の1頭をC頭内に含める
             （同点なら馬番の小さい馬）
    2nd AI … 0〜5頭の範囲で根拠を確認して優先候補にする

  PHP統合時:
    C≧4 で最終候補に保護対象が1頭もいなければ、
    統合おすすめ度が最高の対象馬1頭を追加し、通常順位の最下位と入れ替える。
    既に入っていれば入替不要。保護枠は最大1頭。

  ★AIが出力していない馬をPHPが新規追加するのは禁止。
    1st AIが対象馬を出力しない場合は違反としてログ記録し、
    2nd AIが出力していればそちらを採用。どちらも無ければ通常候補で続行。

  ★この保護枠は「固定上位C頭のみ」「2nd AI独自発見のタイプ別上限」
    「高配当候補を最低1頭入れない禁止事項」に優先する。


■ 5. 統合処理でC頭を確定
────────────────────────────────

  触る場所: _mergeAiResults()

  ・統合おすすめ度順の上位C頭が原則
  ・保護枠が成立する場合のみ最下位1頭と入れ替え
  ・人気帯別上限・大穴条件を理由にC頭を下回らせない
  ・一致馬 = 両AI平均 + 5点（上限100、小数第1位まで保持）
  ・2nd AI独自発見枠は上限であって確保義務ではない（従来どおり）


■ 6. 検証の強化
────────────────────────────────

  ・1st AI の候補行数が C と一致するか検証。不足なら「頭数不足エラー」
    （推測で埋めない／追加AI呼び出し禁止）
  ・2nd AI は0〜5頭。「候補なし|0」は形式不正として扱う
    ※従来は正常扱いだった。仕様が変わった点に注意
  ・2nd AI失敗時は1st AIのC頭で維持（一致加点・独自発見枠は適用しない）
  ・1st AI失敗時はそのレースの予測公開を中止（制御済みエラー）
  ・Cと実際の候補行数が一致しない場合は正常表示せずエラー


■ 7. 回収率閾値 60 → 40
────────────────────────────────

  @ANCHOR-20260926-B12-RECOVERY-THRESHOLD で検索
  private const B12_RECOVERY_LOW_THRESH = 40.0;  へ変更

  ・サンプル30件以上の有効値2種類以上 かつ 2種類以上が40％未満
    → 回収率リスクフラグを記録するだけ
  ・順位への影響は固定100点内の回収率採点だけ。PHPの追加減点は禁止
  ・90％未満のハード除外、64点以下への強制固定、候補復活禁止 → すべて無効
