② 断層学習M4 — 出走全頭の着順記録に変更

よっしーの指示：「全頭分も記録してほしい」「AIが選んだ馬だけの着順では、見逃した馬を検証できない」
→ 本日 UpdateMlResultLabels.php へ実装完了しました。
📋 実装ファイル・場所
UpdateMlResultLabels.php — M4算出部分（merged_numsループからDBクエリに変更）
📋 変更内容
変更前：merged_nums（AIが候補に選んだ馬番のみ）をループしてM4を記録
変更後：t_horse_odds_finder_race_result_history テーブルから該当レースの全馬を取得してM4を記録

・各馬の finishing_position が5以下 → 1（5着以内）
・5を超える → 0（5着以外）
・取消・除外・競走中止（finishing_position が null または 99超） → null
・馬番昇順でソートして保存
📋 変更後のコード概要
// 出走全頭を別クエリで取得 $allResults = DB::table('t_horse_odds_finder_race_result_history') ->where('date', $date) ->where('kaisuu', $kaisuu) ->where('basho_code', $bashoCode) ->where('day', $day) ->where('race', $race) ->get(['num', 'finishing_position']); $m4Data = []; foreach ($allResults as $allRow) { $allNum = (string)(int)$allRow->num; $fp = $allRow->finishing_position; if ($fp === null || (int)$fp > 99) { $m4Data[$allNum] = null; // 取消・除外・競走中止 } else { $m4Data[$allNum] = ((int)$fp <= self::TOP_N) ? 1 : 0; } } ksort($m4Data, SORT_NUMERIC); $m4Json = json_encode($m4Data, JSON_UNESCAPED_UNICODE | JSON_FORCE_OBJECT);
📋 なぜ全頭記録が必要か（よっしーの言葉通り）
・AIが選ばなかった馬の中に本当の狙い目馬がいたかどうかを検証するため
・どの馬を見逃したか、人気薄の偽流入だったかを判定するため
・後回しにすると過去レースの正解データが不足し、学習精度が永遠に上がらないため
・取消・除外・競走中止も通常着順と分けて保存し、学習対象から除外する理由も記録
