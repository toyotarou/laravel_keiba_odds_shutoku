⑤ finishing_position=99 の除外判定を確認すべき コード修正済み
DBのコードを確認したところ、取消・除外・失格は -1 で保存されることが判明しました（99は使用されていません）。
DBの実際の値（SummaryHistoryFinishingPosition.php より）：
NULL / 0 → 未取得（cronの再処理対象）
1〜 → 着順確定
-1 → 中止・除外・取消・失格（再処理対象外）
発見されたバグ（修正済み）：
旧コード：if ($fp === null || (int)$fp > 99)
-1 の馬は「> 99」を通過し、(-1) <= 5 → true → label=1（5着以内と誤判定！）になっていました。
取消馬がMLの正解ラベルに含まれるという重大バグでした。
修正後（UpdateMlResultLabels.php）：
if ($fp === null || (int)$fp <= 0) → null（学習対象外）
NULL/0（未取得）も -1（取消・除外）もまとめてnullとして除外します。
