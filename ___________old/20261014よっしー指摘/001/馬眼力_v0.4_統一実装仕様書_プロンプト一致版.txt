# 馬眼力 第二世代 v0.4 ― 統一仕様・検証用提案

**作成日：2026-10-13／状態：設計統一案・未実装・予測性能未検証。**

## この資料の目的
2026-10-12 に作成した2種類の v0.3（X1〜X6＋Z と Q1〜Q9）を混用しないため、**v0.4の研究・比較基準を一つに固定**する。高配当を演出する好走馬を、1〜6番人気／7〜10番人気／11番人気以下の３帯で幅広く発見し、人気上位の取り逃しも併せて検証する。高配当・的中・回収率改善は保証しない。

## 決定した統一案
- **正式な比較用の構造判定：X1〜X6＋Z／FIRM・MIXED・VOLATILE・UNKNOWN**。エンジニアの10/12報告で `AUDIT_V03_SHADOW` がこの計算法をすでに記録しており、比較を容易にするため採用した。**性能が優れていると立証されたからではない**。
- **人気帯コード：A=1〜6番人気、B=7〜10番人気、D=11番人気以下**。`C`は候補上限数との混同を避けるため使わず、候補数は `target_count` と表記する。後発v0.3の `L` はDへの変換を仕様化し、併存させない。
- **高配当馬の発見経路：市場流入／能力適性／断層位置・時間変化／単複乖離／類似統計・OPI**。旧資格 `F AND (R OR O)` を参考として保存するが、**新案では穴馬を一律削除する条件にしない**。
- **全頭100点の研究用配点：信頼度60（H1〜H5）＋妙味代理40（V1〜V5）**。現行11項目とは別版で保存。妙味点は数学的なEVではない。
- **2つのAI**：1stは5着以内の幅広い捕捉、2ndは独立の見落とし点検。出走馬全頭を同一6分前入力で採点し、PHPで整合・3帯を反映。
- **Q1〜Q9方式は別の研究比較候補として凍結**する。v0.4実運用モードへ混合しない。未知・事故時の挙動と4〜6頭の配分差を含め未使用レースで比較。

## 重要：10月12日時点で本番に起きたこと／起きていないこと
エンジニアの「馬眼力のAI予想の行動指針20261012」の第29章によると、10/12に**記録用シャドー判定をPHPに追加**しただけで、1st/2nd実送信プロンプト・採点・最終候補選出は10/06版から変更していない。これを「新しいv0.4が実装済み」と解釈しない。実PHP・生の監査ログの検証は本提出パックではできていない。

## 主要な判定特徴の違い（対照は概念対応であって同値ではない）
- **X1**：上位境界の消滅または20%以上の縮小を1信号（重み+2）に統合。**Q4/Q5**：消滅+2と、別境界の縮小+1を別々に評価。
- **X2**：単勝W>=2.0に対し複勝P<1.5、k<=10。**Q6**：同趣旨だがk<=6のみ。
- **X3**：3〜6位境界の単勝Wすべて1.5未満。**Q8**：4位〜10位の単勝比が2.5以内。別の混戦像。
- **X4**：7位以下の異なる2頭に複勝21→6で5%以上**または**9→6で3%以上の短縮。**Q7**：21→6で5%以上**かつ**直前9→6で上昇なし。条件は異なる。
- **X5**：中穴付近k=7..10の断層。**Q9**：4〜10位の大きな人気順位変動。性質が異なる。
- **X6**：比較基準率付き類似レースの7位以下3着内率差。Q方式に対応項目なし。
- **Z**：上位に単複一致の持続壁が2境界以上（-2）。Qは**Q1：1人気の強さ、Q2：持続壁、Q3：二重壁**を別々に減点。

**決定の理由は技術的な継続性であり、どちらが予測精度に優れるかを決めたものではない。** Q方式の再検討は別の固定 `research_variant=Q_V03` としてオフライン比較する。X方式の点数・枠配分は10/17・18のレース結果を見てから改変せず、事前に版と設定のハッシュを保存する。

## 1. 正本／観測時点／馬番
- レースID `race_id`、JRAの実出走頭数N、取消状態、6分前スナップショット `snapshot_hash`、全馬の6分前単勝人気、オッズ、出走条件は**DB/PHPの観測値が正本**。AIは元数値を書き換えない。公表人気や確定払戻で事前評価を上書きしない。
- すべての入力は**発走予定6分前までに確定した観測**のみ。馬場・斤量・過去10走なども「予想時点で既知」を満たすこと。未来情報、レース着順、結果を見た閾値変更は禁止。
- 時系列は 21/18/15/12/9/6分前。各馬の単勝 `win_odds` と複勝最小/最大 `place_min/place_max` を区別し、各時点の日時と欠損を保存する。
- 6分前人気で `h[k],h[k+1]` の隣接**馬番ペア**を固定。kは1〜N-1。各時点では順位k/k+1の別の馬へ差し替えず、同じh番号のオッズで比率を計算する。
- `W(k,t)=win(h[k+1],t)/win(h[k],t)`、`P(k,t)=place_min(h[k+1],t)/place_min(h[k],t)`。0、負、欠損、取消は計算不可（null）。6分前の順位入替が21分前に起きていてW<1でも、同じ馬の実測が有効なら比率自体は残し、`rank_crossed=true`を別記する（異なる馬に差替えない）。特定の比較で実際の馬番が無いときのみ当該比率を不明とする。
- 研究初期の単勝壁 `W>=2.00`、複勝補強 `P>=1.50`。端数を丸める**前**の値で判定。壁の上側/下側、位置k、本数、時系列の出現/消滅、縮小/拡大、単勝/複勝一致/不一致をすべて別ログへ。比率の変化と個別馬への流入は同一視しない。

## 2. X1〜X6＋Z（各TRUE/FALSE/UNKNOWN）
以下の閾値は初期仮説。判定対象となる対象馬・境界が存在しなければ**構造的非該当＝FALSE**、存在するが必要なデータが欠ければ**UNKNOWN**。どの特徴も着順や既に選ばれた馬によって変化させない。

| 信号 | 加重 | 機械判定の定義 |
|---|---:|---|
| X1 境界弱化 | +2 | k<=6の有効な固定ペアのどれかで、21分前W>=2.00かつ（6分前W<2.00または `(W21-W6)/W21>=0.20`） |
| X2 単複乖離 | +1 | k<=10の有効な固定ペアのどれかで、6分前W>=2.00かつP<1.50 |
| X3 中位接近 | +1 | k=3,4,5,6が**全て存在・有効**で、6分前Wの最大値<1.50（N<7なら構造的非該当） |
| X4 穴側の絶対支持 | +1 | 6分前7番人気以下の**異なる2頭以上**で、複勝最小が21→6分で5%以上短縮、**または**9→6分で3%以上短縮 |
| X5 中穴の壁 | +1 | k=7..min(10,N−1)の固定ペアのどれかで6分前W>=2.00。該当境界自体が無ければFALSE |
| X6 類似統計 | +1 | 予想時点までの同条件比較が**有効50レース以上**あり、7人気以下3着内進入率が同条件比較基準率より**10パーセントポイント以上高い**。分母と重複排除、母数定義が一致している場合のみ。基準率が未定義・未提供ならUNKNOWN |
| Z 安定上位 | −2 | k=1..min(5,N−1)の**異なる2境界以上**で、21分前W>=2.00、6分前W>=2.00、6分前P>=1.50の全てが成立 |

### 三値の正しい集約方法
- 存在する対象に1つでも条件成立の証拠があればTRUE。確実に成立しないと断定できるだけの有効データがあればFALSE。成立し得る未観測箇所が残る場合はUNKNOWN。
- X4とZのような件数条件は、**成立済み件数が閾値以上ならTRUE**、成立済み+不明の最大件数が閾値に届かなければFALSE、それ以外はUNKNOWN。欠損を自動でFALSEにしない。
- X3は条件がANDなので、4境界のどれか有効かつ >=1.50 ならFALSE、4つとも有効かつ <1.50 ならTRUE、残りはUNKNOWN。
- X6ではユーザー・エンジニアの合意した基準率が無い間はUNKNOWNを必ず残す。とりあえず0%にしない。
- 各フラグに `value`, `raw_evidence`, `missing_reason`, `as_of_time`, `feature_version` を付ける。根拠のない資金流入額や勝率を作らない。

## 3. SとUNKNOWN

`S = 2*X1 + X2 + X3 + X4 + X5 + X6 - 2*Z` （既知TRUE=1、FALSE=0）。これは**確率ではなく研究用の離散指数**。

- 全信号を既知値にしたとき、`S<=1: FIRM`（堅め）、`2<=S<=3: MIXED`（混戦）、`S>=4: VOLATILE`（波乱警戒）。
- UNKNOWN信号が残る場合、各UNKNOWNを0または1にした組合せについて**Sの最小値と最大値**を算出する。ZのUNKNOWNはマイナス方向に作用するので、`S_min`計算でZ=1、`S_max`でZ=0とする。
- 未知が**3信号以上**、または未知の0/1のいずれかによってFIRM/MIXED/VOLATILEの境界をまたぐ場合は `mode=UNKNOWN`。ログには `S_min/S_max`・`unknown_features`・暫定配分を必ず残す。未知が1〜2で**全組合せの判定モードが同じ**なら、そのモードを付すが `mode_has_unknown=true` を必須とする。
- 入力スナップショット自体に整合性がない、取消反映ができない、別時点が混在した場合は `DATA_INVALID` として新案の候補生成を停止し、本番旧方式を維持。`UNKNOWN`（分類不能）と`DATA_INVALID`（入力破損）は別物。
- 分類UNKNOWNでも**研究SHADOWではMIXED配分で仮の候補を作ってよい**。`mode=UNKNOWN, allocation_mode=MIXED_PROVISIONAL`と表示・別ログ保存し、実装承認前に公開候補へ反映しない。将来LIVEを検討する際も、UNKNOWNでは旧方式を保持することを初期安全既定値とする。
- 極端な大波乱`EXTREME 2/3/2`は研究専用で、本比較基準の選出には使わない。必要なら別`variant`として後日再審査。

## 4. 人気帯と候補頭数、3帯目標枠
人気帯は**6分前DB単勝人気で固定**：A=1〜6、B=7〜10、D=11以下。Nは取消を反映した頭数。Cという文字を帯名として使わない。

`target_count = min(N,4)`（N<=8）、`5`（9<=N<=13）、`6`（14<=N<=15）、`7`（N>=16）。N=0は対象外。

| target_count | FIRM A/B/D | MIXED A/B/D | VOLATILE A/B/D |
|---:|---|---|---|
| 7 | **5/2/0** | **4/2/1** | **3/3/1** |
| 6 | **4/2/0** | **3/2/1** | **3/2/1** |
| 5 | **4/1/0** | **3/2/0** | **2/2/1** |
| 4 | **3/1/0** | **2/2/0** | **2/1/1** |
| 1〜3 | 当該実在馬の帯のみ、目標数以下で評価 | 同左 | 同左 |

- 数値は**保証人数でも強制穴枠でもない**。11人気以下が存在しないN<=10では、D枠は物理的に採用不能。A/Bに独立根拠のある候補がいれば`CROSS_BAND_FILL`、いなければ`PARTIAL_COUNT`として不足を記録。N<=6でBも存在しない場合も同様。
- 大穴を公開候補に入れるには事前に説明可能な独立根拠が必要。穴馬資格の不足や好走馬が後で判明したことを理由に枠やモードを事後変更しない。
- 同じ`target_count`/`mode`/設定ハッシュなら全レースで同じ配分表を用いる。Q方式や別配分は**同一版へ混在させない**。

## 6. 穴馬を落とさない「5つの独立根拠」
- `market`: 単複の**絶対**短縮・継続・再加速（相対的流入順位だけでは不成立）。
- `ability`: 過去能力・同条件・適性の根拠があり、現在の単勝人気で過小評価の可能性。
- `gap`: 対象馬がどの壁の上下にいるか、壁の変化がその馬の好走可能性とどう結びつくか、**市場流入と同じ証拠だけでは二重計上しない**。
- `win_place`: 単勝と複勝の支持差、人気順差、実値から説明できる市場の乖離。
- `similar_value`: 統計母数の十分な類似実績・OPI/回収率による補助。ただしOPIだけで好走確率を捏造しない。

`Tier A`=独立**2群以上**、`Tier B`=独立**1群**、`Tier C`=独立根拠なし／全て未検証。証拠が同じ複勝オッズだけなら複数群として数えず一群。7番人気以下でもTier A/Bなら評価対象、**旧F AND(R OR O)=falseだけでは除外しない**。D帯のTier Bでは、最低1つの群が市場・能力・断層など馬自身の実値に結びつくこと。Tier Cを強制採用しない。Tierラベルは候補比較用であり馬券購入推奨ではない。

## 7. 統合前後の選出
1. 入力凍結→断層・構造モード確定→3帯目標凍結→同一6分前データで2AI独立採点→公開候補行/内部全頭JSONの検証。
2. 有効公開候補行またはPHPが**検証済みの内部点**から生成可能な候補のみ統合ランキングへ。補充用の理由文は元データの参照付きで**定型生成**し、証拠なしの後付けストーリーは作らない。
3. +5一致加点は**両AIの公開候補行に同じ馬がある場合だけ**（現行とのA/B比較の際は既存PHPの統合式が正本）。内部JSONに両AIがその馬を採点しただけでは一致とみなさない。実PHPの加算箇所をエンジニアが確認する。
4. 各帯で `score_status=valid`、Tier A/B、出走確認済みの候補を選択。研究初期の帯内ソートは**Tier A→B、次に検証済み統合順位点の降順、信頼度小計の降順、複勝支持の事前順位（値がある場合）、馬番昇順**。スコアが未知の場合は順位捏造禁止（理由記録）。この選出順位は画面に出る公開おすすめ度と別管理する。
5. 3帯の目標を満たす範囲で採用し、ある帯の不足は他帯の次順位Tier A→Bに補充。**採用後に全馬上位C頭で再抽出して確保枠を消さない**。空き枠が埋まらなければ少数公開、HTTP500にしない。
6. **購入判断は別**。回収率2指標の40%未満、低配当、基準点未達などは購入回避/監視に反映し、候補自体を消さない。配当期待値EVは独立に校正した3着内確率／馬券的中確率がないなら「未算定」。確率をAIに架空生成させない。
7. 取消、重複、範囲外馬番、スナップショット相違、JSON形式不正、応答時間超過、1st無効は`UNDETERMINED`/部分結果を区別し、現行の安全な非公開・旧版表示仕様を壊さない。

- 各馬の5独立系統`market/ability/gap/win_place/similar_value`を証拠ID・時刻・母数と一緒に評価。`Tier A=独立2群以上`, `Tier B=1群`, `Tier C=独立根拠なし`。同じ複勝オッズを重複して独立扱いしない。
- 公開候補行が実在馬か、または**検証済み**全頭点からPHPが元データだけで候補行を定型生成できる馬を候補プールとする。根拠のない理由文を作らない。部分点しかない馬を恣意的に上位評価しない。
- 順位づけ（研究初期の固定案）：Tier A→B、検証済み統合順位点の降順、H小計降順、複勝支持順位が妥当かつ取得可能ならそれ、馬番昇順。既存PHPの一致+5は**両AIの公開候補行で同一馬を選んだ場合に限る**。全頭点が両方あるだけでは一致加点しない。実PHPの合成式をエンジニアが検証し、+5と新研究点を別カラムで保持する。

## 5. 3帯の枠確保と補充
1. 6分前人気で`A=1..6`、`B=7..10`、`D>=11`を固定。
2. 固定したquota(A,B,D)それぞれからTierA→Bの採用可能候補を帯内順位順に最大quotaまで採る。目標値と実値を保存。
3. ある帯が不足したら、まだ採られていない**他帯の適格な候補**を統合順位順に空き枠分補う。`CROSS_BAND_FILL`には欠けた帯・補った帯・馬番・証拠ID・順位根拠・元のquotaを保存。N<=10のD枠は物理的に満たせないため別帯へ補充、Tier Cを捏造採用しない。
4. 証拠が足りなければ`PARTIAL_COUNT`として公開可能な頭数のみ。`target_count`は上限で、採用保証ではない。採用後に「最終総合点上位C頭」で穴枠を消す処理は禁止。
5. 重複・架空馬番・取消・人気帯矛盾・時点不一致などは監査し、当該馬の選出を止める。数合わせや結果を見てからの救済は禁止。対象レース一覧自体をHTTP500で止めない。

## 6. 購入判定と画面表示
- 低配当、回収率40%未満、最低基準点、大穴条件不足の印は、候補採否ではなく「見送り」「監視」の購入判定側で用いる。価格期待値EVは校正済み確率と馬券種別払戻の推定が揃う場合だけ計算。OPI・妙味点はEVではない。
- `public_recommendation_score`（旧画面との互換を保った表示点）、`hv10_total_v04`（新研究点）、`merge_rank_score_v04`（選出順位）、`purchase_status`を別管理。本番互換アプリの公開形式を先にテストする。
- プロンプト内の「購入回避フラグで候補を消さない」とPHP実処理の両方が一致するか、レース単位で検証する。

# 断層学習・人気帯選出の段階導入と回収率の厳格比較

## 1. 統一版v0.4の学習関連方針
- 単勝/複勝の固定馬番ペアに沿う断層位置・本数・消失・縮小・拡大・上下の支持・人気帯接近を、レース前の構造特徴量として蓄積。
- M1: 5着以内全馬が6分前1〜6人気、M2: 5着以内に7〜10人気馬あり、M3: 5着以内に11人気以下あり、M4: 各馬5着以内のラベル。M5: 各馬3着以内は追加の独立検証ラベル。M1〜M3のレース事象を特定馬の勝率と誤用しない。

## 2. 検証用データの時間的分離

"""馬眼力 v0.4-X 事前構造判定の参考実装。標準ライブラリのみ。

研究・テスト用。PHP本番コードではない。本モジュールのみでAI/購入候補を作らない。
入出力: ペア辞書 pair[k][21|6]={"W":float|None,"P":float|None}
      馬辞書 runners=[{"popularity":int,"p21":float|None,"p9":float|None,"p6":float|None}]
      similar={"sample_size":int,"delta_pp":float}|None; delta_ppは基準率との差。
すべて発走6分前までの値のみ。フラグのUNKNOWNは一律FALSEにしない。
"""
from itertools import product

THR={"win_wall":2.0,"place_wall":1.5,"shrink":0.20,"short21":0.05,"short9":0.03,"similar_sample":50,"similar_delta_pp":10.0}
WEIGHTS={"X1":2,"X2":1,"X3":1,"X4":1,"X5":1,"X6":1,"Z":-2}
Q={4:{"FIRM":(3,1,0),"MIXED":(2,2,0),"VOLATILE":(2,1,1)},
   5:{"FIRM":(4,1,0),"MIXED":(3,2,0),"VOLATILE":(2,2,1)},
   6:{"FIRM":(4,2,0),"MIXED":(3,2,1),"VOLATILE":(3,2,1)},
   7:{"FIRM":(5,2,0),"MIXED":(4,2,1),"VOLATILE":(3,3,1)}}


def valid(x):
    return isinstance(x,(float,int)) and not isinstance(x,bool) and x>0


def tri_any(conditions):
    """conditions は True/False/None の列。対象が空ならFALSE。"""
    vals=list(conditions)
    if any(v is True for v in vals):return 'TRUE'
    if any(v is None for v in vals):return 'UNKNOWN'
    return 'FALSE'


def tri_at_least(conditions,n):
    vals=list(conditions)
    t=sum(v is True for v in vals)
    if t>=n:return 'TRUE'
    if t+sum(v is None for v in vals)<n:return 'FALSE'
    return 'UNKNOWN'


def b(pair,k,t,v):
    return pair.get(k,{}).get(t,{}).get(v)


def derive_flags(N,pair,runners,similar=None):
    # ペアの6分前の位置番号は1..N-1。辞書欠落はデータ欠損でUNKNOWN。
    def x1(k):
        w21=b(pair,k,21,'W'); w6=b(pair,k,6,'W')
        if valid(w21) and w21<2.0:return False
        if not valid(w21) or not valid(w6):return None
        return w21>=2 and (w6<2 or (w21-w6)/w21>=.20)
    def x2(k):
        w=b(pair,k,6,'W'); p=b(pair,k,6,'P')
        if valid(w) and w<2:return False
        if valid(p) and p>=1.5:return False
        if not valid(w) or not valid(p):return None
        return w>=2 and p<1.5
    def x5(k):
        w=b(pair,k,6,'W')
        return w>=2 if valid(w) else None
    def z(k):
        w21=b(pair,k,21,'W'); w6=b(pair,k,6,'W'); p6=b(pair,k,6,'P')
        if valid(w21) and w21<2:return False
        if valid(w6) and w6<2:return False
        if valid(p6) and p6<1.5:return False
        if not all(valid(v) for v in (w21,w6,p6)):return None
        return w21>=2 and w6>=2 and p6>=1.5
    x1v=tri_any(x1(k) for k in range(1,min(N-1,6)+1))
    x2v=tri_any(x2(k) for k in range(1,min(N-1,10)+1))
    if N<7:
        x3v='FALSE'
    else:
        w=[b(pair,k,6,'W') for k in (3,4,5,6)]
        if any(valid(v) and v>=1.5 for v in w):x3v='FALSE'
        elif all(valid(v) for v in w):x3v='TRUE'
        else:x3v='UNKNOWN'
    def x4_runner(r):
        p21,p9,p6=(r.get('p21'),r.get('p9'),r.get('p6'))
        if not valid(p6):return None
        v21=(p21-p6)/p21>=.05 if valid(p21) else None
        v9=(p9-p6)/p9>=.03 if valid(p9) else None
        if v21 is True or v9 is True:return True
        if v21 is None or v9 is None:return None
        return False
    lower=[r for r in runners if r.get('popularity',10000)>=7]
    # 実在する該当馬が一つでも欠損している場合は必要数に応じUNKNOWN。
    x4v=tri_at_least((x4_runner(r) for r in lower),2)
    x5v=tri_any(x5(k) for k in range(7,min(N-1,10)+1))
    if similar is None or similar.get('sample_size') is None or similar.get('delta_pp') is None:
        x6v='UNKNOWN'
    elif similar['sample_size']<50:
        x6v='FALSE'  # 有効母数の最低条件を満たさない。信頼性は別記する。
    else:x6v='TRUE' if similar['delta_pp']>=10 else 'FALSE'
    zv=tri_at_least((z(k) for k in range(1,min(N-1,5)+1)),2)
    return {'X1':x1v,'X2':x2v,'X3':x3v,'X4':x4v,'X5':x5v,'X6':x6v,'Z':zv}


def score_mode(s):
    if s<=1:return 'FIRM'
    if s<=3:return 'MIXED'
    return 'VOLATILE'


def classify(flags):
    assert set(flags)==set(WEIGHTS),('incorrect signal keys',flags.keys())
    assert all(v in ('TRUE','FALSE','UNKNOWN') for v in flags.values()),'invalid tri-state'
    unknown=[k for k,v in flags.items() if v=='UNKNOWN']
    fixed=sum(WEIGHTS[k] for k,v in flags.items() if v=='TRUE')
    smin=fixed+sum(min(0,WEIGHTS[k]) for k in unknown)
    smax=fixed+sum(max(0,WEIGHTS[k]) for k in unknown)
    # スコア空間に隙間があっても、実際の全組み合わせで判定が揺れるか確認。
    all_modes=set()
    for choice in product((0,1),repeat=len(unknown)):
        val=fixed+sum(WEIGHTS[k]*v for k,v in zip(unknown,choice))
        all_modes.add(score_mode(val))
    mode= 'UNKNOWN' if len(unknown)>=3 or len(all_modes)>1 else next(iter(all_modes))
    return {'mode':mode,'S':fixed if not unknown else None,'S_min':smin,'S_max':smax,
            'unknown_features':unknown,'mode_has_unknown':bool(unknown),
            'allocation_mode':'MIXED_PROVISIONAL' if mode=='UNKNOWN' else mode}


def target_count(N):
    if N<0:raise ValueError('negative N')
    if N<=8:return min(N,4)
    if N<=13:return 5
    if N<=15:return 6
    return 7


def allocation(N,classification):
    cap=target_count(N)
    if cap<4:return {'target_count':cap,'quota':None,'quota_note':'N<=3: no artificial 3-band quota'}
    mode=classification['allocation_mode']
    if mode=='MIXED_PROVISIONAL':mode='MIXED'
    a,b,d=Q[cap][mode]
    assert a+b+d==cap
    return {'target_count':cap,'quota':{'A':a,'B':b,'D':d},
            'quota_note':'SHADOW ONLY; do not force Tier-C to fill physically impossible bands'}
