# 常駐（worker）を立てるときの手順

**いまは何もしなくていいです。** 旗 `BAGANRIKI_R122_JOBS` が `0` のあいだ、
worker が居なくても何も起きません。Job が1本も積まれないからです。

この手順が要るのは、**24日の検証で Job 構成を実際に動かすとき**だけです。

---

## 立てる

```
1. scp "/Users/toyodahideyuki/Desktop/HIDEYUKI/KEIBA/20261021よっしー指摘/出せる版_20261021_1402/systemd/r122-worker.sh" "centos@サーバ:~/"
2. scp "/Users/toyodahideyuki/Desktop/HIDEYUKI/KEIBA/20261021よっしー指摘/出せる版_20261021_1402/systemd/r122-worker@.service" "centos@サーバ:~/"
3. ssh centos@サーバ
4. sudo cp ~/r122-worker.sh /usr/local/bin/r122-worker.sh
5. sudo chmod 755 /usr/local/bin/r122-worker.sh
6. sudo cp ~/'r122-worker@.service' /etc/systemd/system/
7. sudo systemctl daemon-reload
```

ここまでは**置いただけ**です。まだ1枠も動きません。

## 動かす

```
8.  sudo systemctl enable --now 'r122-worker@r122-ai-1st:1'
9.  sudo systemctl enable --now 'r122-worker@r122-ai-1st:2'
10. sudo systemctl enable --now 'r122-worker@r122-ai-2nd:1'
11. sudo systemctl enable --now 'r122-worker@r122-ai-2nd:2'
12. sudo systemctl enable --now 'r122-worker@r122-agg:1'
13. sudo systemctl enable --now 'r122-worker@r122-freeze:1'
```

## 確認する

```
14. systemctl list-units 'r122-worker@*' --all --no-legend
15. tail -40 /var/www/horse_odds_finder/storage/logs/r122_worker.log
```

## 止める

```
16. sudo systemctl disable --now 'r122-worker@*'
```

---

## 立てる前に必要なもの

worker は「待ち行列から取り出して動かす人」です。
取り出す先が無いと動けないので、先に次の3つが要ります。

1. `config/queue.php` の `connections` に `r122` の1節
2. 待ち行列の3表（`jobs` / `job_batches` / `failed_jobs`）をDDLで作る
   **`php artisan migrate` は打たないでください。**
3. `.env` の `BAGANRIKI_R122_QUEUE=1` と `BAGANRIKI_R122_JOBS=1`

1と2は、サーバにすでに入っています（14:02 の実行で確認済み）。
残っているのは3の旗だけです。

**旗を上げると実AIへ送り始めます。** 上げる前に
`BAGANRIKI_R122_TARGETS` に24日の12レースの race_id を並べてください。
空のままだと1レースも送りません（そういう作りにしてあります）。

---

## 枠の数について

出発点として、なるさんの推奨どおり AIを待つ側を各role 2枠、
期限・統合を1枠にしています。

| 待ち行列 | 役 | 枠 |
|---|---|---|
| `r122-freeze` | 入力凍結 | 1 |
| `r122-ai-1st` | 1st のAI待ち | 2 |
| `r122-ai-2nd` | 2nd のAI待ち | 2 |
| `r122-agg` | 期限判定・統合・公開 | 1 |

実機のメモリ・CPU・DB負荷を見て決める、というのが010の指定です。
**性能保証値ではありません。**

`--max-time=3600` で1時間ごとに自分から降り、systemd が立て直します
（PHPの長時間常駐でメモリが膨らむのを避けるためです）。
