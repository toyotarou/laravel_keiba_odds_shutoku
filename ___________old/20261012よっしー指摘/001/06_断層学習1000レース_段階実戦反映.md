# 馬眼力 v0.3 断層学習・1,000有効レースからの段階実戦反映
**この仕様は2026-10-06版の現行「2,000レース＋未使用500レース」の自動改変ではなく、新たな提案。必ず明示承認を経る。**

## 1. 何を学習させるか
- PHP等サーバーの独立したMLモジュールで学習。AIへのプロンプトで「自分で学習しろ」は禁止。
- 6分前人気順位と断層固定馬番ペア、位置k・本数、出現/消滅/拡大/縮小、単複一致・不一致、上下のオッズ、人気の入替、単勝/複勝の流入、コース・距離・馬場・斤量・レース頭数、発走前の履歴・類似情報を特徴量にする。
- M1：5着以内全馬が6分前1〜6人気か。M2：5着以内に7〜10人気が1頭以上。M3：5着以内に11人気以下が1頭以上。M4：各馬が5着以内か。M2/M3は同時成立してよい。追加M5：各馬が3着以内か（別ラベル、別校正・別検証）。
- 事後の着順・確定配当は**結果が確定した後のラベル作成専用経路**へ分離し、予測特徴量のSQL/API/キャッシュには入れない。未来の結果から計算した類似統計や回収率も除外。

## 2. 段階
|状態|必要条件|本番反映|
|---|---|---|
|COLLECT_ONLY|有効0〜999レース|なし。全特徴量/結果ラベルを保存|
|SHADOW|有効1000以上|機械学習・推論を別ログに保存。本番候補には影響なし|
|LIMITED_LIVE|その後新規に発生した、学習にも閾値調整にも使用しない未使用200レース以上で評価合格、ユーザー明示承認|PHPの選出用順位だけ最大±2点相当補正。候補入替最大1頭、公開おすすめ度は変更しない|
|ALLOCATION_LIVE|その後未使用500レース以上で別受入と再承認|3人気帯quotaの最大1枠移動を許可、ML起因入替は順位補正分を含め合計1頭以下|

新規未使用200/500レースは**1,000学習時点より後**に予測を事前凍結したレース。既存の学習/チューニング期間と重複させない。200と500を別期間として取るか累積500とするかは受入前に定義固定（初期案は200を含む累積500）。馬の件数でなく、`race_id + snapshot_hash`で重複排除した「有効レース数」。

## 3. モデルの品質判定
- 時系列学習70%／検証15%／内部テスト15%（開催日単位で境界を跨がない）。未来の検証セットは完全に隔離して閾値・配点・モードを見直したら新しい未使用セットで再評価する。
- M1〜M3: Brier、校正曲線、適合率・再現率、構造帯別母数、過去頻度ベースラインと比較。
- M4/M5: 馬別5着内/3着内の確率校正、Brier、帯A/B/D別捕捉率、候補交換による誤採用・見逃し、期待利益を固定買い方で評価。
- 特にD帯の好走件数が小さい場合は十分な母数と信頼区間なしに枠を増やさない。類似レースの情報量が少ない場合は未適用。
- 合格閾値・許容性能劣化・モデル遅延許容・最小大穴件数は**評価対象の未来の結果を見る前に決める**。小さな見かけ上の改善だけで採用しない。

## 4. 実戦反映の仕方
- 推論が同レースの6分前ハッシュと一致し、`model_version`,`training_cutoff`,`feature_schema_hash`が承認済みで、校正済みM4/M5等と比較元確率が有効な場合のみ、別の`ml_rank_delta`（仮上限±2点相当）を計算。
- 元AI公開おすすめ度、H/V100点、DB値をMLで書換え禁止。統合順位用の派生値だけで比較し、各レース最大1頭だけ交換。受入時に「補正により外れた馬」「入った馬」「理由」を記録する。
- M1/M2/M3はレース単位の波乱構造学習。特定馬の好走確率として使わない。M4/M5は各馬予測。`ALLOCATION_LIVE`でquotaを動かせてもA/B/Dのどこからどこへ1枠変更したか記録。これに伴う交換もML1頭上限内。
- ML未承認・学習不足・モデル校正不良・ハッシュ不一致・入力欠損・予測応答時間超過・モデル性能悪化の場合**MLだけ即OFF**。前段のルールベースv0.3候補へ戻し、未確定/落選理由を残す。
- 毎開催終了後の結果は収集・学習候補に蓄積するが、稼働中のモデルを毎レース自動更新しない。再学習は別版を作成し、再び未来未使用データで評価してから昇格。

## 5. エンジニア提出ログ
最低限 `valid_race_count`, `label_count_M1..M5`, `feature_schema_version`, `model_version`, `model_hash`, `training_last_date`, `stage`, `future_holdout_count`, `future_holdout_results`, `approval_datetime`, `approval_person`, `calibration_summary`, `baseline_comparison`, `snapshot_hash`, `ml_rank_delta`, `ml_quota_shift`, `ml_swap_count`, `fallback_reason` を保存。
ログだけで反事実的に「MLなしなら何が選ばれたか／MLありなら何が入れ替わったか」を再現できるようにする。

## 6. ユーザー受入前の禁止事項
1,000レース到達時の**自動的な本番選出変更は禁止**。過去の勝ち馬をモデルへ暗記させ、同レースで再予測した結果を未使用テストとして数えることは禁止。現在の「2,000+500」の実装を承認なしに書き換えない。
