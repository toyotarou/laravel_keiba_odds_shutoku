## 6. 元値不変の証明（前回ご指摘）

| 項目 | 状態 |
| --- | --- |
| 連結長の切捨てが起きない方法 | **修正済み（今回）** |
| NULL・区切り・型の一意な表現 | **修正済み（今回）** |
| 固定した主キー集合での全件処理 | **修正済み（今回）** |

ご指摘のとおり、`MD5(GROUP_CONCAT(...))` は `group_concat_max_len`
（既定1024バイト）で黙って切り捨てられます。前回までの値は、
切り捨てが起きていないことを確かめずに出していました。

今回から、切り捨ての起きない方法に変えます。

1. **行ごとに MD5 を取り、それを集約**します。連結しないので長さ上限が
   ありません。集約は `BIT_XOR`（順序に依存しない）と `SUM`（件数の
   重みが入る）の両方を出します。
2. **NULL と空文字を区別**します。各列を `COALESCE(col, '\N')` にし、
   区切りは `0x1F`（表示されない制御文字）にします。
   `CONCAT_WS` の NULL 無視は使いません。
3. **主キー集合を固定**します。`MIN(id)`・`MAX(id)`・`COUNT(*)` と
   `BIT_XOR(id)` を併記し、同じ行集合を見ていることを示します。
4. 従来の `MD5(GROUP_CONCAT(...))` も併記し、あわせて
   `group_concat_max_len` と「切り捨てが起きたか」も出します。

前回までの値（`bcba698e…` ほか）は、新しい方法の値とは比べられません。
**今回の値を新しい基準**とします。前回の方法の値も並べて残します。
