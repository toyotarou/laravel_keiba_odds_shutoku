## 2. 重複している部分

正直に書きます。次は**同じことを別経路で確かめています**。

| 重複 | 内容 |
| --- | --- |
| A群の R122-01〜07 と B群 729件 | どちらも mode / mode_status / allocation_mode / mode_policy_id / selection_enabled を見ています。A群は代表6通りを本体の試験として、B群は全729通りを先方の期待値と突き合わせるものです。 |
| A群の R122-T01〜T05 と C群 4件 | どちらも取得期限の境界です。C群は先方の期待値そのもの、A群は同じ条件を本体の試験に取り込んだものです。 |
| A群の R122-E/S系 と E群 | E/S系は閾値の直前・ちょうど・直後という作った値、E群は実データ72レースです。目的が違います（規則の証明と、実データでの確認）。 |

**重複していないもの**

* A群の R122-D01〜D04（集合と頭数）、F01（凍結順位）、H01（hash）、
  R01〜R03・S01（順位と統合）、Q03（評価後不足）、
  P03（取消後の配分）、V01〜V04（応答検証）、U01（表示）
  … これらは先方の合成試験には含まれていません。
* D群（付録A 33件）… 配分表の照合で、他群と重なりません。

## 3. 再現手順

```bash
# 1. 本体の受入試験（全項目の明細つき）
php artisan keiba:ai-analysis-compensate --v04-test-detail

# 2. 本体の受入試験（要約）
php artisan keiba:ai-analysis-compensate --v04-test

# 3. 先方同梱の合成試験
#    validation フォルダを置いたパスを渡します
php artisan keiba:ai-analysis-compensate --r122-cases=/path/to/validation

# 4. 72レースの集計と、本番側との突き合わせ
php artisan keiba:ai-analysis-compensate --mode-check --r122-exact-check \
  --date=2026-10-17,2026-10-18

# 5. r12.2 のテーブルの状態
php artisan keiba:ai-analysis-compensate --r122-status
```

いずれも**読み取りだけ**です。DBへの書き込みも、AIの呼び出しもありません
（`--r122-install` だけは新しいテーブルを作ります。既存テーブルには触れません）。

## 4. 入力・期待値・実測結果の所在

| 群 | 入力 | 期待値 | 実測結果 |
| --- | --- | --- | --- |
| A | 試験コード内に直書き（`v04SelfTest`） | 同上 | `01_受入試験_全項目.txt` / `02_受入試験_要約.txt` |
