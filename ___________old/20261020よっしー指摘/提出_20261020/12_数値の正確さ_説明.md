## 1. 「小数部128桁」と、元契約の「最大128桁・調整後指数 −308〜308」の対応

### 受け取る形

比較に使う数値は、**平たい十進数の文字列だけ**を受け取ります。

```
^(\d{1,128})(?:\.(\d{1,128}))?$
```

さらに、**整数部と小数部を合わせた有効桁が 128 桁を超えたら拒否**します。
切り捨てたり丸めたりはしません。読めない値は「欠損」として三値論理へ流します。

### 調整後指数との関係

平たい十進数しか受け取らないので、調整後指数（adjusted exponent）は

* 最大 … 整数部128桁のとき **+127**
* 最小 … `0.000…1`（小数部128桁）のとき **−128**

の範囲に必ず収まります。契約の **−308〜308 の内側**です。
この範囲を外れる値は、そもそも上の形を満たさないので受け取りません。

### 指数表記

`1.5e3` のような指数表記は、**切り捨てず拒否**します（制御されたエラー）。
対象の入力（単勝・複勝最小）は、DBに十進数の文字列として入っており、
指数表記では来ません。来た場合に黙って解釈しないための拒否です。

### 符号

オッズは正の値だけを受け取ります。`-1.5` や `0`、`0.0000` は無効として扱います
（「取消」などの文字列も同様に、数値へは変換しません）。

## 2. どこに、どの範囲で適用しているか

**限定をやめました。** 判定に使う比較は、すべてこの方式に統一しています。

| 判定 | 比較の形 |
| --- | --- |
| W >= 2.00（単勝の壁） | 下側 >= 2 × 上側 |
| W < 1.50（中位接近） | 2 × 下側 < 3 × 上側 |
| P >= 1.50（複勝の補強） | 2 × 下側 >= 3 × 上側 |
| W < 1（順位入替） | 下側 < 上側 |
| W6 と W21 の大小（拡大／縮小） | 下6 × 上21 と 下21 × 上6 |
| 21→6 の縮小率 >= 0.20 | 4 × 下21 × 上6 >= 5 × 下6 × 上21 |
| 複勝短縮 21→6 >= 0.05 | 19 × 前 >= 20 × 後 |
| 複勝短縮 9→6 >= 0.03 | 97 × 前 >= 100 × 後 |

割り算をしません。掛け算は数字の文字列どうしの筆算（多倍長）で行い、
PHP の整数上限にも float にも触れません。

W・P の**数値**は画面と監査のために残していますが、**判定には使っていません**。

## 3. 順位点

ご指摘を受けて直しました。

順位点は `100 × (K − r + 1) ÷ K` です。K が 3 や 7 のとき割り切れません。
float で持つと `66.666…` となり、統合点の大小や同点の判定が丸めに左右されます。

**分子と分母の組（分数）のまま持ち、比較はたすき掛けの整数**で行うようにしました。
両AI一致の `+5` も、分数のまま足します（`200/3 + 5 = 215/3`）。

検算（R122-S01）:

```
K=3 r=2  → 200/3      （小数なら 66.666…）
K=7 r=3  → 500/7      （小数なら 71.428…）
500/7 > 200/3                         → 成立
200/3 + 5 = 215/3                     → 成立
200/3 と 600/9 は同値                  → 成立
1100/16（68.75）> 200/3               → 成立
```

## 4. 閾値の直前・ちょうど・直後

6か所すべてについて、3点（直前・ちょうど・直後）で確認しています（R122-S02・16項目）。

| 閾値 | 直前 | ちょうど | 直後 |
| --- | --- | --- | --- |
| W >= 2.00 | 1.9999999999 → 不成立 | 2 → 成立 | 2.0000000001 → 成立 |
| P < 1.50 | 1.4999999999 → 成立 | 1.5 → 不成立 | 1.5000000001 → 不成立 |
| W < 1.50 | 1.4999999999 → 成立 | 1.5 → 不成立 | — |
| 縮小率 >= 0.20 | W6=3.9999999999 → 成立 | W6=4 → 成立 | W6=4.0000000001 → 不成立 |
| 複勝短縮 >= 0.05 | 1.8999999999 → 成立 | 1.9 → 成立 | 1.9000000001 → 不成立 |
| 複勝短縮 >= 0.03 | — | 0.97 → 成立 | 0.9700000001 → 不成立 |

小数第10位で判定が変わることを確認しています。
固定の小数4桁であれば、ここはすべて同じ値に丸められて区別できません。

## 5. 手組み入力の代替経路

受入試験は `$pairs` を手で組み立てて渡すため、元値を持ちません。
その場合は、**渡された比の値を十進数の文字列として扱い、同じたすき掛け**で比べます。
float で 2.0 や 1.5 と比べる経路へは戻していません。

元値から作った `$pairs` と、同じ比の値だけを持つ手組みの `$pairs` を
同じ `v04DeriveFlags` へ通し、**X1〜X5・Z の6項目すべてが一致**することを
試験にしています（R122-S03）。
