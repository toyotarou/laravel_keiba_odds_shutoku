2. R122-02 ─ 正確な数値の範囲

これは本物の不具合でした。見つけていただいて助かりました。

報告書に「1万倍の整数で保持」と書きましたが、それは検証コマンド側だけの話でした。本番側（AiControllerのv0.4判定）は、float で割り算して小数4桁に丸めた比を2.00 や 1.50 と比べていました。全体の話のように書いたのは誤りです。

直した内容

桁数の上限を決めるのをやめました。割り算も float も使いません。十進数の文字列のまま、たすき掛け（分子×相手の分母）を多倍長整数で比べます。

W>=2.00      ⇔ 下側 >= 2×上側
W<1.50       ⇔ 2×下側 < 3×上側
P>=1.50      ⇔ 2×下側 >= 3×上側
縮小率>=0.20 ⇔ 4×下21×上6 >= 5×下6×上21
複勝短縮>=0.05 ⇔ 19×前 >= 20×後
複勝短縮>=0.03 ⇔ 97×前 >= 100×後

いただいた確認項目へ

どの入力項目・桁範囲に限定されているか

限定をやめました。単勝・複勝最小の元値、そこから作るW・P・短縮率のすべてを、同じ方式で扱います。受け付ける形は「整数部1〜128桁」と「小数部1〜128桁」、有効桁の合計128桁までです。

小数第5位を切り捨て・丸め・拒否していないか

していません。1.00001 と 1.00000 の大小がつくことを試験にしました。読めない形（「取消」など）は数値へ変換せず、欠損として扱います。128桁を超えたら制御されたエラーにします（黙って丸めません）。

大きな積・比でも整数上限やfloatへ落ちないか

落ちません。掛け算は数字の文字列どうしで筆算と同じやり方をします。30桁×30桁が60桁になること、30桁どうしの大小が正しくつくことを試験にしました。PHPの整数上限にも float にも触れません。

信号・順位点・派生値・原文保存まで正確か

信号（X1〜X5・Z）は上のとおりです。W・Pの数値は画面と監査のために残していますが、判定には一切使っていません。順位点は 100×(K−r+1)÷K で、K・r は整数です。原JSONは LONGTEXT で原文のまま保存します。

いちばん大事な確認

本番側と検証側に同じ入力を通し、X1〜X5・Zが一致するか全レースで突き合わせました。

3. 途中で2つ壊しました
