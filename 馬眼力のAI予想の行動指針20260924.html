馬眼力のAI予想の行動指針

2026年9月24日
依頼されている内容は全て実装されています

よっしーさんからいただいたご指摘（9月13日〜22日の36件のメモ）と、仕様書（2026年9月21日版）をもとに、AI予想の仕組みを最初から最後まで、プログラム本体で1つずつ点検しました。

このページでは、ご指摘の内容を1問ずつ「〜できているか」の形に書き出し、それぞれの対応状況と中身を書いています。全部で111問あります。

  • → 対応できています：ご指摘・仕様書のとおりに動くようになっています（110問）
  • → 仕様の範囲で対応しています：仕様書の別のルールとの関係で、できる範囲で対応しているもの（1問）。理由と、変える場合の方法を書いています

「今回の点検で直しました」と書いてあるものは、以前の報告では対応済みとされていたものの、プログラム本体を確認したところ仕様とずれていたため、今回直したものです。

0. いちばんの目的

目的は「当てること」ではなく、長い目で見て回収率を上げることです。人気馬ばかり当てても配当が安いので、「来そうか（信頼度）」と「そのオッズで買う価値があるか（妙味）」の両方で馬を評価します。

予想の順番（仕様書の【最終PHP処理順序】どおり）

  1. AIに聞く前に、システムが市場妙味基礎点などを計算する（AIには送らない）
  2. 1st AI（Claude）に予想させる。答えがおかしければ公開しない
  3. 1st AIが問題なく答えたときだけ、2nd AI（DeepSeek）に予想させる
  4. 馬番でまとめ、「両方が選んだ馬」「1st AIだけ」「2nd AIだけ」に分ける
  5. 学習用のデータを保存する（今は保存だけ）
  6. 統合おすすめ度（両方が選んだ馬は平均＋5点）を出す
  7. 能力適性補正・高配当総合点を出す（検証中は記録だけ）
  8. 最低基準点 → 低配当除外 → 回収率フィルター（ここではまだ上限をかけない）
  9. 2nd AIだけの馬の採用を判定する
  10. おすすめ度順に並べ、人気帯ごとの上限をかける
  11. 馬券判定を付ける（検証中は記録だけ）
  12. 出走頭数ごとの上限（4〜7頭）で確定する。頭数合わせはしない
  13. 厳選穴レースを判定し直す

1. 2つのAIの役割と、AIに渡すデータ

9月13日・17日・18日のご指摘より

1.2nd AI（DeepSeek）は、「1st AIが選ばなかった馬を見る係」ではなく、1st AIとは別に出走馬全頭を独立して評価しているか

→ 対応できています

2nd AIは1st AIの答えを見ずに、同じデータで全頭を評価します。1st AIと同じ馬を選ぶことも、違う馬を選ぶことも自由です。「1st AIと違う馬を選べ」とは指示していません。

2.2nd AIに「1st AIとの不一致を目的にしない」「根拠のない逆張りは禁止」と伝えているか

→ 対応できています

2nd AIへの指示に「入力データと逆方向の判断をする場合は、入力内にある反証根拠を明記。根拠のない逆張りは禁止」と入れています。「逆の馬を選ぶのも正しい」という古い表現は残っていません。

3.過去成績・能力適性のデータを、DeepSeekだけでなくClaudeにも同じ内容で渡しているか

→ 対応できています

両方のAIに、各馬の直近最大10走の成績と今回のレース条件を同じ内容で渡しています。

4.過去成績は「最大10走」になっているか（5走ではないか）

→ 対応できています

最大10走です。

5.過去成績に、騎手・斤量・馬体重・通過順・上がり・着差・距離・コース・クラスなど、DBにある項目を入れているか

→ 対応できています

DBにある項目はすべて入れています。DBにない項目は推測して作らず、入れていません。

6.2nd AIへ過去成績が二重に送られていないか

→ 対応できています

1st AI用のプロンプトにすでに過去成績が入っている場合は、2nd AI側で追加しません。送信直前にも「過去成績の見出しが1回だけか」を自動で確かめ、ログに残します（下の「確認のしかた」参照）。

7.能力・適性を評価するための「第3のAI」や、追加のAI呼び出しを作っていないか

→ 対応できています

AIはClaudeとDeepSeekの2つだけです。能力・適性の採点は、それぞれのAIが1回の分析の中で行います。

8.1st AIにも能力適性の6項目採点（100点満点）を指示しているか

→ 対応できています

両AIに同じ6項目（基礎能力25・近走内容20・コース距離適性20・脚質展開15・上がり位置取り10・斤量騎手など10）で採点させ、A〜Dの区分を付けさせています。

9.選出理由の最初に「能力適性:A（82点）。」の形で書かせているか

→ 対応できています

両AIとも、選出理由の冒頭にこの形で必ず書くよう指示しています。システムはここから点数を読み取ります。

10.両AIに渡すのは「同じデータ」だが、システム指示・出力形式・候補上限・厳選穴レース行／レース指標行の有無は、AIごとに分けているか

→ 対応できています

共通の本文・データは再利用し、1st AI専用の部分（厳選穴レースの判定ルール、1行目・2行目の出力指示、候補0頭時の指示）を2nd AI用から取り除いたうえで、2nd AI専用の指示を足しています。完成した送信文は2つのAIで同じにはなりません。

11.Claude（1st AI）には、仕様書に書かれた正式なシステム指示だけを使っているか

→ 対応できています

仕様書の1st AIシステム指示の文をそのまま使っています。古いシステム指示との併用はしていません。

12.両AIへ「3分前のオッズ・確定オッズ・確定人気・着順・払戻金」などの発走後の情報を渡していないか

→ 対応できています

渡しているのは計測開始から発走6分前までのデータだけです。AIにも「発走後の情報を使ったり推測したりしない」と指示しています。

13.過去成績を集めるとき、予想するレースより後の成績が混ざっていないか

→ 対応できています

今回の点検で、同じ日の後のレースの成績が混ざる可能性がある箇所を見つけて直しました。予想するレースより前の成績だけを使います。

14.人気順・OPI・流入ランク・推定確定オッズ・断層の判定を、AIが自分で計算し直さないようにしているか

→ 対応できています

すべてシステムが計算した値を渡し、「再計算・変更しない」と両AIに指示しています。AIが返した人気順やオッズは、システムがDBの値と照らし合わせて確認します。

15.AIに「最大5頭」「最大7頭」と伝え、頭数を埋めさせていないか（「5頭選出」になっていないか）

→ 対応できています

「最大◯頭」「最低基準未満の馬を追加して◯頭へ埋めてはいけません」と指示しています。

16.PHPが計算した人気帯別・合計の上限が7頭より少ない場合、少ない方をAIに伝えているか

→ 対応できています

1st AIには「合計最大◯頭」として、人気帯別の上限の合計（7頭以下）を伝えています。

17.出走馬の一覧は馬番順で渡しているか

→ 対応できています

馬番順で並べて渡しています。

2. オッズの時系列データ

9月22日のご指摘より

18.複勝最小オッズを、計測前・21分・18分・15分・12分・9分・6分前の全時点で両AIへ渡しているか

→ 対応できています

「複勝時系列（最小）」として全時点を渡しています。

19.推定確定複勝オッズを「最小・最大・誤差」の形で渡しているか

→ 対応できています

「推定確定複勝最小・推定確定複勝最大・補正誤差」を渡しています。

20.推定確定複勝オッズが作れなかったとき、6分前のオッズで代わりに埋めたりせず、「データなし」として扱っているか

→ 対応できています

「－（補正データなし）」と表示し、6分前の値で置き換えません。今回、作れなかったことをログにも残すようにしました（仕様の受入チェック5）。

21.複勝が4時点未満しかないとき、2時点だけから「続けて下がっている」と推測していないか

→ 対応できています

4時点未満なら「複勝継続流入」は「不明」にします。

22.断層の時系列は「6分前の人気順」を基準にして、同じ馬を馬番で追いかけているか（時点ごとに別の馬と比べていないか）

→ 対応できています

AIに渡す断層時系列は6分前人気順が基準です。学習用の記録も、今回6分前人気順を基準にした記録を追加し、断層の出現・消滅・拡大・縮小の判定もこれで行うようにしました。

3. おすすめ度（100点）の付け方

9月13日・18日・22日のご指摘より

23.おすすめ度は「信頼度60点＋妙味40点」の固定配点で、AIが配点を変えられないようになっているか

→ 対応できています

両AIに同じ配点表（信頼度7項目・妙味4項目）を渡し、項目の追加・削除・配点変更を禁止しています。

24.2nd AIに「自分の判断で採点」ではなく、「固定配点を厳守し、各項目の指定範囲内で独立して採点」と伝えているか

→ 対応できています

この表現で伝えています。

25.能力適性の点数（A=20・B=14・C=7・D=0）を、おすすめ度に足していないか

→ 対応できています

足していません。能力適性の点数は「高配当総合点」（検証中の数字）の計算にだけ使います。

26.高配当総合点・市場妙味基礎点を、おすすめ度に足したり平均したりしていないか

→ 対応できています

別々に計算して記録しています。混ぜていません。

27.両AIが選んだ馬のおすすめ度は「2つの平均＋5点（上限100点）」になっているか

→ 対応できています

その計算です。

28.両AIが選んだ馬の点数を、小数第1位まで保ったまま順位や基準の判定に使っているか

→ 対応できています

小数第1位のまま使い、アプリに表示するときだけ整数にします。

29.推定確定複勝最小1.5倍未満の馬は、妙味の小計を原則5点以下にするよう指示しているか

→ 対応できています

AIに指示しています。

30.回収率が90%未満の種類が2つ以上ある馬は、AIの採点で64点以下にするよう指示しているか

→ 対応できています

AIに指示しています。システム側でも除外します（5章）。

31.回収率はサンプル数とセットで見て、データがない・0レース・「－」は中立として扱うよう指示しているか

→ 対応できています

両AIに指示しています。

32.選出理由は「1頭につき改行なしの1行」で、4〜5行の文章になっていないか

→ 対応できています

「候補1頭につき改行なしの1行」と指示しています。

33.AIが自分で作った「〜%の確率」などを選出理由に書かせていないか

→ 対応できています

書かせていません。

34.推定確定複勝1.5倍未満の馬の妙味小計が5点以下かを、システムで直接確かめているか

→ 仕様の範囲で対応しています

仕様で「AIの出力に内訳・小計を追加しない（アプリの形式を変えない）」と決められているため、AIの小計そのものは受け取れません。そのためシステムは、おすすめ度と能力適性点から「信頼度の上限（57点＋能力適性点）」を使って、妙味小計が5点を超えている証拠がないかを確かめ、記録しています。小計を直接確かめるには出力形式の変更が必要になります。変更をご希望の場合はご指示ください。

4. AIの回答のチェックと、失敗したときの扱い

9月13日・18日・21日のご指摘より

35.AIを呼ぶのは1レースにつき1st AI・2nd AIの1回ずつ（合計2回）だけで、自動の再試行はしていないか

→ 対応できています

Claudeも DeepSeekも1回だけ呼びます。通信エラーでも再試行しません。今回の点検で、2nd AIの保存結果を誤って消して何度も呼び直していた不具合を見つけて直しました。まとめ直しが必要なときも、保存済みの回答を使います。

36.1st AIが8頭以上を答えたら、システムが勝手に削らずに「形式不正」として予想を公開しないようにしているか

→ 対応できています

8頭以上なら公開しません（制御済みエラー）。今回、保存済みの結果から返すときにもこの判定が効くように直しました。

37.2nd AIが6頭以上を答えたら、2nd AIの答えを無効にして1st AIだけで続けているか

→ 対応できています

その扱いです。

38.1st AIの上限（7頭）と、まとめた後の表示の上限（4〜7頭）を混ぜていないか

→ 対応できています

別々です。例えば10頭立てでClaudeが7頭答えても正常として扱い、まとめた後に5頭へ絞ります。

39.1st AIの答えが空・形が違う・必要な2行がない場合は、予想を公開せず「制御済みエラー」を返しているか

→ 対応できています

その扱いです。2nd AIだけの候補を通常の予想として出すことはありません。

40.1st AIの「正常な候補0頭」（厳選穴レース行とレース指標行だけがある）と「回答失敗」を区別しているか

→ 対応できています

区別しています。

41.1st AIに「候補が0頭なら1行目と2行目だけを出す（『該当馬なし』などを書かない）」と指示しているか

→ 対応できています

今回の点検でこの指示が抜けていたので、仕様書の文のとおりに追加しました。

42.2nd AIの「候補なし|0」を、失敗ではなく正常な0頭として扱っているか

→ 対応できています

正常な0頭として扱い、この文字列はアプリへ渡しません。

43.1st AIが失敗しているときや、まだ終わっていないときに、2nd AIを呼んでいないか

→ 対応できています

今回、2nd AIを呼ぶ前に1st AIの結果を確認するよう直しました。未完了なら「まだ終わっていません」、失敗なら制御済みエラーを返し、DeepSeekは呼びません。アプリも1st AI→2nd AIの順に呼ぶように直しました。

44.AIの答えの馬番が実在するか、重複していないか、人気順・6分前オッズがDBと合っているか、点数が0〜100の整数かを確かめているか

→ 対応できています

すべてシステムがDBと照らし合わせて確かめ、合わないものは除くかDBの値で直します。

45.AIの答えの読み取りで、「馬番: 3」のように空白が入った正しい答えまで捨てていないか

→ 対応できています

確かめる処理と読み取る処理を同じものにして、食い違わないようにしています。

46.AIの回答原文と、読み取りに失敗した理由をログに残しているか

→ 対応できています

残しています。

47.出力の指定行に「★」「☆」などの記号が混ざっていないか

→ 対応できています

混ざっていません。送信直前に自動で確かめ、ログに残します。

5. 候補を絞る順番とルール

9月18日・19日・21日・22日のご指摘より

48.フィルターの順番は「最低基準点→低配当除外→回収率フィルター→順位確定→人気帯上限」になっているか

→ 対応できています

今回の点検で、以前は人気帯上限・頭数上限で絞った「後」にフィルターをかけていたことを見つけ、仕様どおり「前」にかけるよう直しました。外れた馬の分は次の馬が繰り上がります。

49.フィルターは、両AIの答えをまとめて統合おすすめ度（平均＋5点）を出した「後」にかけているか

→ 対応できています

まとめて点数を出した後、人気帯上限の前にかけています。

50.最低基準点：70点以上＝本候補、60〜69点で10番人気以内＝補欠、11番人気以下は55点以上＋大穴の条件、それ以外は除外、をシステムで判定しているか

→ 対応できています

システムで判定しています。

51.低配当除外は「推定確定複勝最小1.5倍未満」かつ「推定確定単勝3.0倍未満」の両方を満たす馬が対象になっているか

→ 対応できています

両方を満たす馬だけが対象です。

52.低配当の例外は「断層最上位グループ」「単勝・複勝の両方が複数時点で継続流入」「サンプル30件以上で回収率110%以上が2種類以上」の3つを全部満たすとき（AND）だけか

→ 対応できています

3つ全部を満たすときだけです（ORではありません）。

53.例外を満たさない低配当馬は、69点以下にするだけでなく、システムで候補から外しているか（補欠として残っていないか）

→ 対応できています

システムで候補から外しています。

54.回収率ハード除外は、各馬に表示している3つの回収率（過去回収率・OPI帯別・フェーズパターン別）を使い、「サンプル30件以上の有効値が2種類以上あり、そのうち2種類以上が90%未満」の場合だけか

→ 対応できています

その条件だけです。馬名ごとに独自に計算し直すことはしていません。データがない馬は除外しません。

55.11番人気以下を選ぶ条件（複勝が続けて下がっている・7番人気以下の中で複勝流入ランク1〜2位・単勝と複勝の両方に流入・下位進入を裏付ける形）を守っているか

→ 対応できています

AIに守らせたうえで、今回システムでも確かめるようにしました。データがなくて確かめられない条件は「不明」とし、それだけでは外しません（「不明を条件未達と扱わない」というルールのため）。

56.大穴進入度が1〜2なら11番人気以下は0頭、3なら最大1頭にしているか

→ 対応できています

今回、一部の断層位置のレースにしか効いていなかったのを見つけ、すべてのレースに効くように直しました。

57.断層位置別・人気帯別の上限（1〜6番人気／7〜10番人気／11番人気以下）を仕様書の表どおりに使っているか

→ 対応できています

仕様書の表どおりです。

58.まとめた後の表示は、8頭以下4頭・9〜13頭5頭・14〜15頭6頭・16頭以上7頭を超えないか（16頭以上が6頭になっていないか）

→ 対応できています

その上限です。16頭以上は7頭です。

59.基準に届く馬が少ないとき、頭数合わせをしていないか

→ 対応できています

していません。基準を満たす馬がいなければ、少ない頭数のまま（0頭もあり）で終わります。アプリでも、0頭のときに除外済みの馬を表示しないよう直しました。

60.上限で外れた枠を、すでにフィルターで除外した馬で埋めていないか

→ 対応できています

埋めていません。

61.能力適性だけを理由に、両AIが選ばなかった馬をシステムが追加していないか

→ 対応できています

追加していません。

62.能力適性Dでも、強い市場の根拠がある馬を自動で除外していないか

→ 対応できています

能力適性だけでは除外しません。

6. 2nd AIだけが選んだ馬（独自発見）の扱い

65.F1〜F8のデータがないとき、「不明」として true の数に入れていないか

→ 対応できています

入れていません。
