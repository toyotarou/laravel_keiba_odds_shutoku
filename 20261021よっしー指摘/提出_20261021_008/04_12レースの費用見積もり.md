## 1　回数（ご指定のとおりです）

対象は**非公開12レース**。

| | 回数 |
|---|---|
| 1st（初回）12レース × 1回 | 12 |
| 2nd（初回）12レース × 1回 | 12 |
| **初回の小計** | **24** |

内訳は Anthropic が 12〜24回、DeepSeek が 12〜24回です。

**これは新経路の検証分だけです。** 既存運用の呼び出し（毎分の先回り `--quiet-skip` と 23:20 の補完）、10月25日、別日の事前試験は、この24〜48回には含めません。別枠で出します。

自動再送はしません（`maxAttempts: 1`）。失敗したレースを無断で足して上限を増やすこともしません。訂正は1レース1roleにつき最大1回で、枠が `UNIQUE(snapshot_id, role, attempt_no)` なので構造として増やせません。

## 2　レースの選び方

**結果を見る前に決めます。** 10月24日の出走表が出た時点で12レースを選び、`race_id` の一覧を先に記録して提出します。

- 可能な範囲で少頭数／多頭数、複数場、近接した発走時刻を含めます
- 18頭立てがあれば必ず含めます。無ければ**実出走頭数の最大のもの**を入れ、別途**無課金の18頭固定入力試験**で補います（下の4章）
- 堅い／混戦／波乱の出現数は**実測として記録**します。内訳をそろえるために結果を見て入れ替えることはしません
- 失敗したレース・候補0のレースも、12レースの結果に含めます

これは動作・完了率・費用を調べる12レースです。**複勝回収率100％以上を認定できる標本数ではありません。**

## 4　トークン数（まだ出しません）

**バイト数をトークン数として扱いません。** ご指摘のとおりです。

いま分かっているのは**バイト数だけ**です。

| | 値 |
|---|---|
| 13頭のレースの `user` 本文 | 267,887 バイト（`log/14_固定入力.txt`） |
| 15頭 | 310,949 バイト（`log/07_本番入力.txt`） |
| 過去走を外した場合（13頭） | 127,853 バイト |

**トークン数は、課金ゼロで実測できます。**

Anthropic には `POST /v1/messages/count_tokens` があり、**料金はかかりません**（出力を生成しないため。1分あたりのリクエスト数の制限だけがあります）。DeepSeek 側は公開トークナイザで数えます。

そこで、10月24日より前に次を1回だけ行い、**実トークンで見積もりを出し直します。**

1. 代表レース（少頭数・多頭数・18頭固定入力）の `INPUT_JSON` を本番の経路で作る（既に `--r122-prod-input` でできています）
2. その本文を `count_tokens` へ通し、**1st の入力トークン数**を得る（課金なし）
3. 同じ本文を DeepSeek のトークナイザへ通し、**2nd の入力トークン数**を得る（課金なし）
4. 訂正の本文（`r122AssembleFix` の出力）も同じく数える
5. 出力トークンは、正常出力14本の実物（`mat/validation/normal`）の JSON を数えて上限の目安とする
6. 24回時と48回時の金額を、実トークン × 上の単価で出す

**この手順そのものに課金は発生しません。** 実AIへの送信は0回のままです。

## 5　いま言えること・言えないこと

**言えること**

- 回数は24回（初回のみ）〜48回（訂正込みの上限）です。構造として、これを超えません
- 自動再送はありません
- キャッシュは使っていないので、入力は毎回フルで課金されます
- トークン数は課金ゼロで実測できます

**言えないこと**

- **金額は、まだ出せません。** トークン数を実測していないためです
- 1レースあたりの出力トークン数も未測定です
- DeepSeek の現行単価は未確認です

金額を出すのは、上の4章の実測が終わってからにします。**バイト数から換算した数字は出しません。**
