## 6章　厳密JSON

### (1) 数値と文字列の区別

**ご指摘のとおりでした。** 丸まる数値を引用符で囲んで `json_decode` していたので、

```
{"a":1.99999999999999999999}     ← JSON上は数値
{"a":"1.99999999999999999999"}   ← JSON上は文字列
```

が返却値では同じPHP文字列になっていました。**型が消えるので、再保存で数値が文字列に化けます。**

**直した内容**

走査中に、**どの経路がJSON上の数値だったか**を控えます（`number_paths`）。経路は `["horses",0,"scores","H1"]` のような形で持つので、キーに記号が入っていても境目が決まります。原トークン・正確な十進値・JSON上の型がこれで結び付きます。

再保存は `BaganrikiJson::reserialize($value, $number_paths)` です。数値だった位置は引用符を付けずに書き戻します。**AIが最初から引用符付きで返した文字列は `number_paths` に載らないので、勝手に数値として扱うことはありません。**

### (2) Unicodeエスケープした重複キー

**ご指摘のとおりでした。** `\uXXXX` を復号せずキー比較用の文字列へ足していたので、`{"a":1,"a":2}` が重複キーの拒否を**すり抜けて**いました。復号してから比べるようにしました。代理対は組み立て、片方だけの代理は受け取りません。

### 試験（明細を出します）

`log/10_厳密JSONと桁.txt` の R122-J05（22項目）。合格件数だけでなく、1項目ずつ出しています。

| 見ていること |
|---|
| 丸まる数値も値は読める／最初から文字列の方も同じ値に見える |
| **しかし数値だった位置は控えている**（1件）／文字列だった位置は控えない（0件） |
| **再保存すると数値は数値に戻る**／文字列は文字列のまま |
| AIが引用符付きで返した数は数値に変えない |
| 混在（整数・丸まる小数・文字列の数・普通の小数）でも型が入れ替わらない |
| 入れ子（`horses[0].scores.H1`）でも数値の位置が分かり、再保存で戻る |
| 有効桁128も再保存で数値に戻る |
| **閾値の両側**：満点ちょうど（18）は整数のまま／わずかに超える数（18.0000000000000000001）は整数にならない |
| **エスケープした同じキーの重複を見つける**（`a`）／素のままの重複も見つける／違うキーなら通す |
| エスケープを復号した値になる（`馬` → 馬）／代理対を組み立てる／片方だけの代理は断る |
| `extract` も型の印を引き継ぐ／`extract` の結果も再保存で数値に戻る |

### 「もう一度集計して同じ値を確認した」は誤りでした
