2　修正
・BaganrikiTime::normalizeRaceStartClockは、H:MM、HH:MM、H:MM:SS、HH:MM:SSを秒までの表記にそろえる。従来の厳密な時計・日付の検証を通し、24:00や09:60を翌日・翌時刻へ繰り上げない。予想入力の取得、凍結前の確認（指定時刻／DB正本）、取得時の前倒し、凍結巡回、送信・公開の期限計算で共用する。
・新規の予約、送信許可、受領、予算待ち後の送信直前、新規公開の書込み直前は、発走済みならRACE_STARTEDで止める。W2新規処理で正本の状態が分からない場合はRACE_STATUS_UNAVAILABLE。時刻・日付の破損は従来どおり理由付きで拒否する。送信許可前に止めた場合は未送信として扱う。
・保存済みの公開IDと本文の照合、同一受領の再通知、および期限を過ぎた送信の後処理には、それぞれ既存の読戻し・後処理の経路を使用する。新しいAIを呼ばない。

3　Laravelの接続
・両AIの入力や送信済みプロンプトに発走状態を加えない。W2のサーバー側ライブ状態にrace_startedを追加する。SDK用のリクエストを用意する前、予算確認後、新規公開を保存する直前に、正本からその都度作る。キュー投入時の値を再利用しない。
・送信・新規公開用の期限取得はBaganrikiWorker::deadlines($snap, $live, $lockRace, true)。新規公開時は現行の書込トランザクションでlive_stateとintentをロックし、$lockRaceをtrueとする。成功した返値のrace_startedとlive_closeを同じ読取りから使う。元のスナップショットには02に記した対象IDをrelease_versionとして保存する。
  $deadline = BaganrikiWorker::deadlines($snap, $live, $lockRace, true);
  if (!$deadline['ok']) { throw new \RuntimeException($deadline['code']); }
  $state['race_started'] = $deadline['race_started'];
  $state['live_close_at'] = $deadline['live_close'] === null
      ? null : BaganrikiTime::toJst($deadline['live_close']);
・上記は既存アダプターに追加する部分。従来のrace_id、snapshot_hash、now、all_cancelledと、公開時の取消一覧・3版・role_journalは02の手順どおり構成する。例外はその処理の保留・ロールバックに渡し、予算枠を確保済みなら既存の未送信精算を使う。
・状態フラグの有効値は真偽値、整数0/1、PDOの文字列「0」「1」。欠落・null・曖昧な値をfalseに置き換えない。発走済みを認めた時点で新規送信・公開を止める。過去の保存済み公開は、同一intentの記録をreplayIdで照合して読み出す。
・受領検査と新規ジョブの版はw2-r15.5。R15.4までの保存済み本文・証跡・診断と新規処理を区別する。両AIのプロンプト・スキーマはR15、E3/E5計算器はv0.1.4。
