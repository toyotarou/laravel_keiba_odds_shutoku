作成日：2026-10-25

0．目的と適用範囲
目的は「似た過去レースで、同じ人気順位の馬が実際に好走した頻度」を推定すること。
3着以内用 E3 と5着以内用 E5を別々に出す。全馬を計算対象とする。
E3は高配当につながる人気薄の検証、E5は候補選出の検証に用いる。
いずれも的中・利益を保証しない。馬券の金銭的な期待収益を表す式ではない。

本仕様は、実装後に照合するための独立した比較案。現在のr12.2、選出枠、
波乱度、人気帯、プロンプト、学習段階、公開経路は変更しない。
この式は実データで学習・検証済みのモデルではない。
v0.1の対象範囲はJRA平地の芝・ダート。障害・地方等への適用は別途検証する。
PHPファイルは数式部分の参考実装であり、実運用への組込みを完了したコードではない。

1．現行の期待数値との区別
現行の式：
  legacy_expectation_ratio_i
    = 類似過去レースの同じ人気順位における単勝オッズ中央値
      / 対象馬iの現在の単勝オッズ

例：中央値10倍 / 現在5倍 = 2.0、中央値10倍 / 現在20倍 = 0.5。
したがって、この式で1より大きい場合は現在オッズが過去中央値より低い。
画像にある「1より大きいほど現在オッズが高い」という説明とは逆になる。
逆数に変更せず、計算式と表示説明の照合項目として記録する。
この比だけから、過去の同人気馬が好走した割合は分からない。

新しいE3/E5は定義が異なるため、現行項目を上書きせず別項目に保存する。
旧比率と新スコアの大小・単位を直接比較しない。旧比率を新スコアに掛けない。
旧比率は照合用に保持し、v0.1の距離には下記の元オッズ情報を使う。
旧比率を追加特徴として使う場合は、各過去時点の中央値を再現したうえで
追加効果を別の版で検証する。現在作った中央値を過去へ流用しない。
旧方式の「RMSEから類似度70%以上への変換」は本資料では確定していない。
以下の新しい距離Dは独立した定義であり、旧70%条件を置き換えない。

2．入力契約と過去データ
時刻の基準はJST。対象レースの名目発走時刻、実際の凍結時刻、
各オッズの観測・取得時刻、データが利用可能になった時刻を保持する。
r12.2で承認された6分前・21分前スナップショットと採用期限をそのまま利用し、
新指標のために再取得・締切延長しない。過去も同じ採用規則で再構成する。
例：6分前の採用期限がT-6分+30秒なら、その期限後に届いたデータは使わない。
予測時点に分からなかった確定オッズ・確定人気・結果は入力特徴に使わない。

対象レースおよび過去レースで保存するもの：
  race_id、JST開催日、nominal_start_at、freeze_at
  N：凍結時点で出走予定の頭数
  surface：TURFまたはDIRT
  race_type：FLAT
  distance_metres：正の距離
  class_group：NEW / MAIDEN / C1 / C2 / C3 / OP / L / G3 / G2 / G1
  馬ID、馬番、6分前単勝オッズ、21分前単勝オッズ
  スナップショット時刻・利用可能時刻、取消時刻・状態
  過去レースの公式着順、結果確定・利用可能時刻、失格・中止等の状態
class_groupは固定の対応表から作り、名称をLLMに推測させない。
新馬=NEW、未勝利=MAIDEN、1/2/3勝クラス=C1/C2/C3、
リステッド=L、その他のオープン=OP、重賞=G1/G2/G3とする。

人気順位r：
  凍結した6分前単勝オッズの昇順で1～Nの一意の順位を作る。
  同じオッズなら馬番の昇順。安定したソートを使い、対応表を保存する。
  新モジュール内の順位であり、既存r12.2の人気帯・同値処理を変更しない。
  既存人気帯との順位差が出た場合は双方の順位をログに残す。
  過去レースも「当時の6分前順位」を使う。最終人気順位へ並べ替えない。
  21分前オッズは、6分前順位rの同じ馬を馬IDで対応させる。
  「21分前のr番人気の別の馬」を参照しない。

過去の基準集団P：
  対象日のJST 00:00より前に結果が利用可能で、開催日が対象日の1～730日前、
  N・surface・race_typeが対象レースと同じレース。
  完全な6分前オッズと公式結果を持つ一意なrace_idだけを採用する。
  同日レースはv0.1では使用しない。
  学習・検証時もその予測対象日より前のデータだけでPを作り直す。
  21分前オッズが欠ける過去レースは基準集団には使えるが、後述の近傍には使わない。
  確定オッズを欠損した6分前オッズの代わりに使わない。

取消・結果：
  凍結前の取消はNから除く。凍結後の取消がある過去レースは、
  v0.1の学習・評価本集計から除外し、除外件数・割合・結果を別記する。
  対象日の凍結後取消は既存r12.2の規則に従い、元の凍結値を上書きしない。
  公式に中止・失格が確定した馬はY3=Y5=0。
  結果未確定・不明は0とせず、そのレースの学習・評価を保留する。
  同着は公式着順で判定する。

3．中心となる方程式
対象馬iの6分前順位をrとする。過去レースjでは同じ順位rの馬を対応させる。
kは3または5。同じ過去サンプル集合から両方を計算する。

  Y(j,k) = 公式着順がk着以内なら1、それ以外は0
  M       = 基準集団Pのレース数
  B(k,r)  = Pのうち、順位rの馬がk着以内だったレース数

  p0(k,r) = ( B(k,r) + 1 ) / ( M + 2 )                ……基準好走率

M=0の場合はp0をnullとし、新スコアも未算出とする。0.5を代入しない。
+1と+2は、少数例で基準率が0や1に張り付くのを和らげる初期設定。
最適値と確認された定数ではない。

近傍集合S(i)と重みw(i,j)を第4節で決める。

  W(i)   = Σ[j∈S(i)] w(i,j)
  A(k,i) = Σ[j∈S(i)] w(i,j) × Y(j,k)

  p_raw(k,i) = { A(k,i) + λ × p0(k,r) } / { W(i) + λ }

  E(k,i) = 100 × g( p_raw(k,i) )                       ……改良期待スコア

初期λ=20。λは補正の強さであり「20%固定の配点」ではない。
実際の近傍データの比重は W/(W+λ)、基準率の比重は λ/(W+λ)。
W=80なら80%と20%、W=5なら20%と80%になる。
W=0でも基準率があればp_raw=p0。ただしBASELINE_ONLYと明記する。
基準集団と近傍は重なるため、この式を独立標本による厳密な事後分布とは呼ばない。

gは予測値を実績に合わせる校正関数。未学習の間はg(p)=pとして比較用に表示し、
RAW_UNCALIBRATEDを付ける。未校正の32点を、検証済みの好走確率32%と断定しない。
第5節の校正を適用した場合のみCALIBRATION_APPLIEDを付ける。
校正を適用しただけでも、実運用の性能が検証済みとは限らない。

4．「似ている」の定義と重み
O6(c,r)：対象レースcの6分前順位rの単勝オッズ。
O6(j,r)：過去レースjの当時の6分前順位rの単勝オッズ。
O21(c,i)、O21(j,r)：それぞれ同じ馬の21分前単勝オッズ。
lnは自然対数。全オッズは有限の正数であること。

4-1．レース全体の人気構造
  q(c,l) = ln( O6(c,l+1) / O6(c,l) )       l=1,…,N-1
  q(j,l) = ln( O6(j,l+1) / O6(j,l) )

  d_profile² = { Σ[l=1…N-1] (q(c,l)-q(j,l))² / (N-1) } / 0.35²

N=1の数式上の処理はd_profile²=0。通常の対象レースで使う想定ではない。
自然対数を使うのは、オッズ比の差を共通の尺度に置くため。

4-2．対応する馬のオッズ水準
  d_price² = { ln( O6(c,r) / O6(j,r) ) / 0.70 }²

4-3．同じ馬の21分前から6分前への動き
  m(c,i) = ln( O21(c,i) / O6(c,r) )
  m(j,r) = ln( O21(j,r) / O6(j,r) )
  d_move² = { (m(c,i)-m(j,r)) / 0.35 }²

オッズが下がった馬を必須とする条件ではない。過去との動きの近さを測る。

4-4．距離とクラス
  d_distance² = { (距離c - 距離j) / 400 }²
  d_class²    = クラス区分が同じなら0、違えば1

4-5．合成距離
  D(i,j)² = (d_profile²+d_price²+d_move²+d_distance²+d_class²) / 5

5成分は同じ係数だが、尺度が異なるため「予想への寄与が各20%」という意味ではない。
0.35、0.70、400および同じ係数は比較開始用の仮設定である。
最適化する場合は過去の訓練・調整期間だけで選び、最終評価期間を使わない。
どれかを欠損したとき、残りの成分に重みを再配分して別の距離にしない。
対象馬の必要入力が欠ければ新指標を未算出とし、既存の選出からは除外しない。
過去例の必要入力が欠ければ、その例だけ近傍候補から外す。

4-6．近傍の抽出と重み
基準集団のうち、距離の全入力がそろい、D²≤9の過去レースを候補とする。

  AgeDays(j) = 対象JST開催日と過去JST開催日の差（日）
  w(i,j) = exp{ -D(i,j)² / (2h²) } × 2^{ -AgeDays(j)/H }

初期値：h=1、H=365日。
距離が小さい例、時期が近い例ほど重くする。
w降順、D²昇順、過去開催日降順、race_idの辞書順昇順で決定的に並べ、
先頭K=200件までをS(i)とする。選択に結果Yを使わない。
同じ過去race_idを重複して入れない。
wを合計1や最大1に正規化しない。λはこの絶対的な重みの合計に対して働く。
最大件数や尺度を変えればλとの釣合いも変わるので、新しい版として記録する。

標本の診断：
  n_eff(i) = W(i)² / Σw(i,j)²    （W=0のとき0）
  local_weight_share = W(i)/(W(i)+λ)

v0.1.2以降の内部計算では、n_effの分子分母を最大重みで割った値から計算し、
極小の重みの二乗が0へ丸められる問題を避ける。Wそのものは正規化しない。
p_rawは同値な「近傍比重×近傍好走率＋基準比重×基準好走率」で計算する。
W=0の場合はp0を直接返す。重み関数もhの二乗で直接割らない同値式へ変更した。
数学上の定義と初期パラメーターは変更していない。

n_effとlocal_weight_shareは参考情報であり、的中の信頼確率や信頼区間ではない。
同一日・同一場などの相関は、このn_effだけでは補正されない。

5．校正関数g
3着以内と5着以内の順序を壊さないため、最初は両者に同じ単調増加関数を使う。

  x = clip(p, ε, 1-ε)   、ε=0.000001
  logit(x) = ln{x/(1-x)}
  sigmoid(z) = 1/(1+exp(-z))
  g(p) = sigmoid{ a×logit(x) + b }

aの初期探索範囲：0.1～10、b：-10～10。
係数未学習ならa,bはnullで保存し、校正を適用しない。
単体計算の確認用にa=1,b=0を渡すことはできるが、それを実績で校正済みと扱わない。

学習方法：
・訓練/パラメーター調整期間 → 校正期間 → 最終評価期間を日付順に分ける。
・校正期間の各予測も、そのレースより前の情報だけでp_rawを再計算する。
・係数は次の損失を最小にする。校正に使った期間を最終評価に再利用しない。

  L(a,b) = (1/R) Σ[校正レースt]
           (1/Nt) Σ[馬i]
           (1/2) Σ[k∈{3,5}]
           {-Y(t,i,k)ln(g(p_raw(t,i,k)))
             -(1-Y(t,i,k))ln(1-g(p_raw(t,i,k)))}

【数値実装の指定・四次精査追補 2026-10-26】
上式は数学上の定義。プログラムで各損失を求めるときは、次の同値な式を使う。
  x = clip(p_raw, 0.000001, 0.999999)
  z = a × ln{x/(1-x)} + b
  loss(z,Y) = max(z,0) - Y×z + log1p(exp(-abs(z)))
L(a,b)は、このlossを上式どおり「各レース→各馬→3着内/5着内」で平均する。
log1p(v)は小さいvでもln(1+v)を安定して計算する専用関数。
ln(1+v)へ書き換えたり、100倍・丸め後の表示スコアを学習に渡したりしない。
Yは0または1。p_rawと係数の有限性・範囲を確認してから計算する。

理由：p_raw=0.99、a=10、b=10でも、倍精度のsigmoidは1.0へ丸まる。
その後ln(1-g)を直接取る実装ではln(0)が発生する。
安定式ではY=0の損失は約55.9511985013、Y=1では約5.0199944268e-25となり有限。
基準率やスコアの定義、校正係数の範囲、レースごとの平均方法は変更しない。
校正学習モジュールは本ZIPの実装範囲外。今回明確化したのは、その実装時の計算方法。
四次精査時の参考実装v0.1.3には、学習や係数の自動更新を追加していない。
五次精査のv0.1.4にも、校正係数の学習処理は含めていない。
再現と検算：audit/verify_calibration_loss.py、audit/fourth_review_run.json。

Rは校正レース数、Ntは当該レースの対象頭数。
距離に必要な入力と基準集団が全馬でそろい、W>0の馬だけで構成されるレースを
校正の対象とする。対象外の件数・理由は別記する。
BASELINE_ONLYに局所モデル用の校正を流用しない。基準率は未校正の別区分で表示する。
最適化の初期値は(a,b)=(1,0)。有界の数値最適化で最小化し、
収束した係数・ソルバー名・版・許容誤差・学習期間・対象範囲を記録する。
収束しない、学習終了時刻が予測時点以降、対象範囲が違う、係数が欠ける場合は適用しない。

同じgならp_raw3≤p_raw5からg(p_raw3)≤g(p_raw5)が保たれる。
ただし両目的が同時に十分校正されることは保証されない。
3着以内・5着以内、人気帯、支持データの多寡ごとに実績とのずれを確認する。
必要なら、順序を制約した別の校正方式を次版で検討する。
レース内の全馬合計が必ず3や5になる設計ではなく、連系馬券の同時確率でもない。

6．出力・欠損・表示
独立テーブルまたは独立ファイルへ出力し、現在のr12.2 JSON Schemaに勝手に追加しない。
PHPから計算した値をFlutterへ渡す。Flutter側で異なる式を再実装しない。

必須の保存項目：
  race_id、horse_id、horse_number、freeze_at
  6分前の新モジュール順位・既存人気帯順位、N
  formula_version、implementation_version、parameters_hash、input_snapshot_hash、source_identity
  comparison_only=true、validated_for_live=false
  legacy_expectation_ratio（入手できる場合のみ。現行値をそのまま別保存）
  M、B3、B5、p0_3、p0_5
  neighbour_count、W、A3、A5、n_eff、local_weight_share、lambda
  p3_raw、p5_raw、p3_cal、p5_cal、trial_score_3、trial_score_5
  score_basis、support_status、欠損/除外理由
  calibration_id、calibration_cutoff、参照した過去race_id・D²・w

support_statusの初期ルール：
  UNAVAILABLE_INPUT    必須入力がない（アダプター側で判定）
  OUT_OF_SCOPE         v0.1の対象範囲外（アダプター側で判定）
  UNAVAILABLE_BASELINE M=0
  BASELINE_ONLY        M>0かつW=0
  LOW_SUPPORT          M<100、近傍の正の重み件数<20、W<10、n_eff<15のいずれか
  COMPARISON_READY     上記以外

これらの閾値は処理用の仮設定。COMPARISON_READYも実運用承認の意味ではない。
LOW_SUPPORTは注意表示であり、既存r12.2から馬を落とす条件にしない。
未算出はnullと理由を返す。0点に置換しない。

計算・比較には丸め前の値を使い、表示だけ100倍して小数第1位へ四捨五入する。
PHP参考実装はPHP_ROUND_HALF_UPを使う。
p_calは校正未適用ならnull。trial_scoreは適用した場合だけp_cal、その他はp_rawを使う。
BASELINE_ONLYでは校正を適用しない。計算実装もW=0なら校正を抑止する。

7．計算例（すべて架空データ）
基準集団M=198。
同じ人気順位の3着以内はB3=19回、5着以内はB5=39回。

  p0_3 = (19+1)/(198+2) = 0.10
  p0_5 = (39+1)/(198+2) = 0.20

近傍100例の重みを各0.8とし、3着以内15例、5着以内35例とすると、
  W=80、A3=12、A5=28、λ=20。

  p3_raw = (12+20×0.10)/(80+20) = 0.14
  p5_raw = (28+20×0.20)/(80+20) = 0.32

未校正の試算表示：E3=14.0、E5=32.0、score_basis=RAW_UNCALIBRATED。
5着以内データの方が多いため、同じ入力集合ではE3≤E5になる。

重みが等しくても0.8を1へ変更すると、λに対する近傍の比重が変わる。
同じ100件という理由だけで重みを件数に置き換えない。

8．選出との接続・馬眼力としての検証
この指標だけを全馬で高い順に並べると、人気馬へ偏る可能性がある。
波乱度に応じた既存の人気帯・選出枠を守ったうえで、同じ人気帯内の比較に使う。
人気薄の枠を1～6番人気で埋める仕様変更は行わない。
好走する根拠があるかを各馬で確認し、人数合わせで低人気馬を追加しない。

v0.1には能力・騎手・血統・展開・当日の馬場偏り等を直接入れていない。
それらを含む既存判断をこの式だけで置き換えない。
5つの距離成分や旧比率を「独立した複数の根拠」として重複加点しない。
既存判断と情報が重なるため、無条件に最終点へ足さない。
同じ凍結入力・同じ人気帯枠・同じ頭数で、現行版と追加候補版を比較する。
r12.2のCOLLECT_ONLY等の既存状態を勝手に変更しない。
最初の2レース等の小規模試験は動作・照合確認であり、精度向上の証明ではない。

評価項目：
・3着以内/5着以内それぞれの予測帯と実測好走率の対応。
・Brier score、log loss、人気帯別の校正表。
・同一の選出頭数で、実際の3着以内/5着以内馬を何頭拾えたか。
・7～10番人気、11番人気以下での3着以内の捕捉率と選出馬の好走率。
・波乱度ごとの人気帯枠の遵守。支持データ不足・未算出・取消による除外率。
・買い目・購入時刻・金額規則を固定して比較できる場合だけ回収率も算出。
  好走スコアだけから回収率を換算しない。
・日付順の複数区間で再現するかを調べ、大きな払戻し1回で採用を決めない。
採用基準と評価期間は最終評価を見る前に決める。
成績を見てから条件や期間を選び直した場合は、新しい検証として扱う。

9．提供物・実装時の確認
ExpectedValueV01.php：
  距離D²、時系列重みw、基準率、補正、校正適用、表示値の純粋な参考実装。
  DB取得、時刻照合、過去候補の抽出、並べ替え、校正係数学習、API接続は含まない。
  parameters.jsonを自動読込する実装ではなく、v0.1の定数をコード内に固定している。
  パラメーター変更時はコード・JSON・formula_version・検証値を同時に更新する。

parameters.json：
  初期設定の一覧。最適化済みの推奨値という意味ではない。
test_vectors.json、verify.php：
  手計算可能な数値例・欠損時の計算・不正入力・単調性の照合。
  エンジニア環境では、PHP 8.0以上で「php verify.php」を実行する。
verification_summary.json：
  作成環境で実際に実行した数値検査と、実行できていない検査を区別して記録。

提供環境にはPHPがないためPHP実行・Laravel接続・Flutter表示は未検証。
Pythonによる独立した数値照合を実施する。PHPの合格とは扱わない。
本番組込み前にはPHPでの照合に加え、時刻・取消・欠損・同値オッズ・馬ID対応、
将来データ混入の防止、過去時点の再現を実データで確認する。

五次精査補足（実装v0.1.4）：
W・A3・A5・n_effと近傍平均の内部合計にNeumaierの補償和を使う。
通常の加算では重み0.1の100件が9.99999999999998となり、W<10と誤判定する例がある。
補償和で加算誤差を抑制し、W=10の境界を確認する試験を追加した。
閾値を緩めたり表示用の桁数で先に丸めたりはせず、計算後の原値を比較する。
